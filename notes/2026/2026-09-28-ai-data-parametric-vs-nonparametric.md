## 질문

> **모수적(parametric) 알고리즘과 비모수적(non-parametric) 알고리즘의 차이는 무엇인가? 각각 언제 쓰는가?**
>
> 원문 항목: *Parametric vs non-parametric algorithms*

## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 한 문장 정의

| | 정의 |
|---|---|
| **모수적(Parametric)** | 함수의 **형태를 미리 정해 두고**, **정해진 개수**의 파라미터만 학습한다. 데이터가 아무리 늘어도 **파라미터 수는 그대로**다 |
| **비모수적(Non-parametric)** | 함수의 형태를 **미리 정하지 않는다.** 모델의 크기(복잡도)가 **데이터와 함께 커진다** |

> 🏫 **비유**
> - **모수적**: 옷을 **기성복 사이즈(S/M/L) 중에서 고른다.** 치수 몇 개만 정하면 끝이다. 빠르지만 체형이 특이하면 안 맞는다.
> - **비모수적**: **맞춤 정장.** 몸을 재는 만큼 옷이 몸에 맞춰진다. 잘 맞지만 재야 할 게 많고, 잘못 재면 그 실수까지 옷에 들어간다.

### 가장 흔한 오해 — "비모수 = 파라미터가 없다"

> ❌ 비모수적 모델은 파라미터가 없다
> ✅ 비모수적 모델은 파라미터 수가 **고정되어 있지 않다** — **데이터에 따라 늘어난다**

```text
결정 트리 : 데이터가 많아질수록 분기(노드)가 늘어난다 → 파라미터가 있다. 다만 개수가 정해져 있지 않다
KNN       : 학습된 가중치는 없지만, 훈련 데이터 전체를 들고 있다 → 데이터 자체가 모델이다
```

[[2026-08-19-ai-data-kmeans-vs-knn]]에서 KNN을 "학습되는 파라미터가 없다"고 설명했는데, **KNN만 놓고 보면 맞는 말이다.** 하지만 **비모수적 모델 전반의 정의는 "파라미터가 없다"가 아니라 "파라미터 수가 데이터 크기에 따라 늘어난다"** 이다.

### 대표 알고리즘

| 모수적 | 비모수적 |
|---|---|
| 선형 회귀 | **KNN** |
| 로지스틱 회귀 | **결정 트리** (깊이 제한이 없을 때) |
| 나이브 베이즈 | 랜덤 포레스트 |
| 선형 판별 분석(LDA) | **커널 SVM** |
| 퍼셉트론 | 가우시안 프로세스 |

**커널 SVM이 왜 비모수적인가?** [[2026-09-01-ai-data-svm]]에서 본 대로 커널 SVM은 **서포트 벡터들**로 결정 경계를 표현한다. 서포트 벡터가 몇 개일지는 **데이터에 따라** 정해지므로 모델의 크기가 고정되지 않는다. 반면 **선형 SVM**은 가중치 벡터 `w` 하나로 끝나므로 모수적이다.

## 기준 답변

### 트레이드오프

| 항목 | **모수적** | **비모수적** |
|---|---|---|
| **가정** | 강하다 (함수 형태를 미리 정함) | 약하다 |
| **필요한 데이터** | **적어도 된다** | **많이 필요하다** |
| **학습 속도** | 빠르다 | 느릴 수 있다 |
| **예측 속도** | **빠르다** — 파라미터 몇 개로 계산 | 느릴 수 있다 — KNN은 매번 전체 데이터를 훑는다 |
| **해석** | 쉽다 (계수를 읽으면 된다) | 어려운 경우가 많다 |
| **가정이 틀리면** | **과소적합** — 아무리 데이터를 줘도 못 맞춘다 | 데이터가 충분하면 결국 맞춘다 |
| **주된 위험** | **높은 편향** | **높은 분산(과적합)**, 차원의 저주 |

**예측 속도 차이를 숫자로 보면**

```text
선형 회귀   : 특징 d개 → 곱셈 d번이면 끝                → O(d)
KNN         : 훈련 데이터 n개와 전부 거리를 잰다         → O(n·d)

n = 100만, d = 100 이면
  선형 회귀 : 100번
  KNN       : 1억 번
```

**비모수적 모델은 데이터가 모델이라서, 데이터가 커질수록 예측도 느려진다.**

### 편향-분산 관점 — 이것이 핵심 축이다

[[2026-08-05-ai-data-bias-variance]]의 축 위에 그대로 올라간다.

```text
모수적    : 강한 가정 → 탐색할 함수 공간이 좁다 → 편향↑ 분산↓
비모수적  : 약한 가정 → 탐색할 함수 공간이 넓다 → 편향↓ 분산↑
```

| 상황 | 유리한 쪽 | 이유 |
|---|---|---|
| **특징 수·관계 복잡도에 비해 데이터가 적다** | **모수적** | 분산이 주된 문제라 가정으로 억제하는 게 이득 |
| **데이터가 많고 관계가 복잡하다** | **비모수적** | 가정 없이 데이터가 형태를 정하게 둔다 |
| **실제 관계가 대략 선형이다** | **모수적** | 가정이 맞으면 편향도 거의 없다 — 손해 볼 게 없다 |

> 💡 **[[2026-09-11-ai-data-cnn]]의 귀납적 편향 논의와 같은 구조다.** 거기서 "귀납적 편향은 데이터를 대신하는 지식"이라고 정리했다. **모수적 모델의 함수 형태 가정도 귀납적 편향이다** — 데이터가 부족하면 이득이고, 넘치면 제약이 된다.

### 경계 사례 — 신경망은 어느 쪽인가

**기술적으로는 모수적이다.** 구조를 정하면 파라미터 수가 고정되고, 데이터가 늘어도 파라미터 수는 그대로다.

**그런데 성격은 비모수적에 가깝다.**

```text
파라미터 수가 워낙 많다 (수백만~수천억)
  → 표현할 수 있는 함수 공간이 사실상 매우 넓다
  → "함수 형태를 미리 정한다"는 모수적 모델의 약점이 거의 없다
```

그래서 **"형식상 모수적, 실질상 비모수적처럼 동작한다"** 고 말하는 게 정확하다. 면접에서 신경망을 한쪽에 단정적으로 넣기보다 **이 구분을 짚는 편**이 좋다.

### 언제 무엇을 쓰나

| 상황 | 선택 |
|---|---|
| 특징 수에 비해 데이터가 적고, 해석이 중요하다 | **모수적** (선형·로지스틱 회귀) |
| 빠른 예측이 필요하다 (실시간 서빙) | **모수적** |
| 데이터가 충분하고, 관계를 모른다 | **비모수적** (트리 계열, 커널 방법) |
| 고차원이다 | 모수적 쪽이 안전 — 비모수적 방법은 **차원의 저주**에 약하다 |

**차원의 저주가 비모수적 모델에 특히 아픈 이유**: 비모수적 모델은 "가까운 데이터를 참고"하는 방식이 많은데, 차원이 높아지면 **모든 점이 서로 멀어져** "가깝다"는 개념 자체가 무너진다. KNN이 대표적이다.

### 실무 관점 — 부스팅이 기본값인 이유와 예외

**"데이터가 적다"는 샘플 개수의 절대값이 아니다.** 특징 수와 관계의 복잡도에 비해 데이터가 얼마나 적은지를 뜻한다. 실제로 표 형태 데이터에서는 **수백 개만 있어도 CatBoost·XGBoost가 선형 모델보다 잘 나오는 경우가 많고**, 실무 기본값으로 부스팅을 쓰는 것이 합리적이다.

**부스팅이 적은 데이터에서도 버티는 이유 — 이론과 어긋나는 게 아니라 이론대로다**

- 부스팅은 **규제가 강하게 걸린 비모수 모델**이다. 트리 깊이 제한, 작은 학습률, 조기 종료, 잎당 최소 샘플 수가 **모델이 움직일 범위를 좁혀 분산을 낮춘다.**
- 얕은 트리를 쌓으면 결과적으로 **특징별 곡선을 더한 모델**에 가까워진다. 선형처럼 덜 흔들리면서 직선보다 유연하다.
- CatBoost는 기본 설정이 과적합을 억제하도록 짜여 있어(ordered boosting 등) 튜닝 없이도 작은 데이터에서 무난하다.

→ **"비모수 모델 + 강한 규제"로 편향과 분산을 둘 다 적당히 잡은 것**이다.

**선형 모델이 이기거나 비슷한 경우**

| 상황 | 이유 |
|---|---|
| **샘플 수에 비해 특징이 많다** (예: 100행 × 50열) | 트리가 나눌 근거가 부족해 분산이 커진다. 규제된 선형 모델(Ridge·Lasso)이 더 안정적인 경우가 많다 |
| **실제 관계가 거의 선형·가산적이다** | 가정이 맞으면 선형 모델은 편향이 거의 없고 분산도 작다. 부스팅은 계단 모양 근사라 이득이 없다 |
| **잡음이 매우 크다** | 부스팅이 잡음을 패턴으로 착각해 따라가기 쉽다 |
| **학습 범위 밖을 예측해야 한다** | 트리는 외삽을 못 한다(아래 참고) |

**트리의 외삽 한계**

```text
집값 예측, 학습 데이터의 평수가 10~50평일 때 80평을 넣으면

선형 회귀 : 기울기를 따라 더 높은 값을 예측 (외삽)
XGBoost   : 50평 근처 잎의 값이 그대로 나온다 → 학습 때 본 최댓값 위로 못 올라간다
```

추세가 계속 오르는 데이터(수요 예측 등)에서는 추세를 선형 모델로 먼저 빼고 나머지만 트리로 맞추는 방식을 쓴다.

**실무에서 하는 순서**

1. **선형 모델을 기준선(baseline)으로 먼저 돌린다.** 이길 거라서가 아니라, 비용이 거의 안 들고 해석이 쉬워 **"부스팅이 이 정도는 넘어야 한다"** 는 기준점이 되기 때문이다.
2. **부스팅을 돌리고 교차 검증으로 비교한다.** 샘플이 100개 수준이면 폴드 하나에 20개 남짓이라 점수가 크게 흔들리므로, **반복 교차 검증**으로 평균과 분산을 함께 본다.
3. **차이가 작으면 선형을 택하기도 한다.** 해석성·외삽·배포 단순성까지 따지면 그쪽 이득이 더 클 수 있다.

> **실무 기본값은 부스팅이 맞고, 이론이 알려 주는 것은 "언제 그 기본값이 틀릴 수 있는지"다.** 특징이 많을 때, 관계가 거의 선형일 때, 잡음이 클 때, 외삽이 필요할 때 — 이 네 가지가 부스팅을 의심해 볼 신호다.

### 한 문장 요약

> **모수적 모델은 함수 형태를 미리 정하고 고정된 수의 파라미터만 학습해 빠르고 데이터가 적어도 되지만 가정이 틀리면 과소적합한다. 비모수적 모델은 형태를 정하지 않고 데이터와 함께 복잡도가 커져 유연하지만 데이터가 많이 필요하고 과적합과 차원의 저주에 약하다. 핵심은 "파라미터가 없느냐"가 아니라 "파라미터 수가 데이터에 따라 늘어나느냐"다.**

## 내가 정리한 내용

> 오늘은 정리 대신 **대화에서 직접 제기한 두 가지 반론**을 기록한다. 이론 질문 세 개의 모범 답은 요청에 따라 대화에서 제시했고, 핵심은 위 `기준 답변`에 들어 있다.

- **실무에서는 모수/비모수를 거의 구분하지 않는다.** 라벨이 있는지 없는지는 구분하지만, 모수/비모수는 모델이 처리해 주니 딱히 따지지 않았다.
- **데이터가 극도로 적지 않은 이상, 100개 이상만 돼도 CatBoost·XGBoost가 선형 모델보다 성능이 좋지 않나?**

## 검토 결과

### 확인된 부분

- **실무 경험에서 나온 반론 두 개가 모두 타당했다.**
  - 모수/비모수는 실무에서 **먼저 고르는 항목이 아니다** — 라벨 유무처럼 "무엇을 할 수 있는지"를 정하는 첫 갈림길이 아니라, 모델을 고르면 따라오는 성질이다.
  - 표 형태 데이터에서 **수백 개 수준이면 부스팅이 선형보다 나은 경우가 많다** — 실무 기본값으로 맞다.
- 두 반론 덕분에 이 주제를 **정의 암기**가 아니라 **실무 현상(외삽·서빙 비용·기준선)을 설명하는 도구**로 정리할 수 있었다.

### 보강 포인트

#### ① "모델이 처리해 준다" — 모델을 고르는 순간 가정도 고른 것이다

| | 내용 |
|---|---|
| **전** | 모수/비모수는 모델이 처리해 주니 구분할 필요가 없다 |
| **후** | 이름을 붙이지 않을 뿐, **모델을 고르면 그 가정도 함께 고른 것**이다. 그 결과가 **외삽 실패, 데이터에 비례하는 서빙 비용, 소량 데이터에서의 흔들림**으로 실무에 드러난다 |

#### ② "100개면 부스팅이 이긴다"는 경향이지 규칙이 아니다

| | 내용 |
|---|---|
| **전** | 100개 이상이면 부스팅이 선형보다 성능이 좋다 |
| **후** | **대체로 그렇다.** 다만 기준은 샘플 수가 아니라 **특징 수·관계 복잡도 대비 데이터량**이고, 특징이 많을 때·관계가 선형일 때·잡음이 클 때·외삽이 필요할 때는 선형이 이기거나 비슷하다 |

#### ③ 처음 설명의 교정 — "데이터가 적다"의 기준

처음 설명에서 "데이터가 적을 때 모수적이 유리하다"고만 쓴 것은 **너무 단순했다.** 샘플 **개수**가 아니라 **특징 수와 관계의 복잡도에 비해** 적은지가 기준이다. 본문 표 두 곳을 이 기준으로 고쳤다.

### 심화: 부스팅은 이론의 예외가 아니라 이론의 사례다

부스팅이 적은 데이터에서도 잘 나오는 것은 "비모수가 데이터 많을 때 유리하다"는 말과 충돌하지 않는다.

```text
순수한 비모수 모델 (깊이 제한 없는 트리, k=1 KNN) : 편향↓ 분산↑↑ → 적은 데이터에서 과적합
규제된 비모수 모델 (얕은 트리 + 작은 학습률 + 조기 종료) : 편향↓ 분산↓ → 적은 데이터에서도 버팀
```

**규제가 곧 "가정을 일부 되돌려 넣는 것"** 이다. 깊이 제한은 "관계가 아주 복잡하지는 않다"는 가정이고, 조기 종료는 "적당히 단순한 해가 낫다"는 가정이다. 결국 **편향-분산 손잡이를 어디에 두느냐의 문제**로 모인다 — [[2026-08-05-ai-data-bias-variance]]

### 심화: 신경망의 이중적 성격

| | 파라미터 수 | 함수 모양의 제약 | 실제 성격 |
|---|---|---|---|
| **선형 회귀** | 고정, 적음 | 강함 (직선) | 모수적 |
| **신경망** | 고정, **매우 많음** | **거의 없음** | 형식은 모수적, 행동은 비모수적 |
| **결정 트리** | 데이터 따라 늘어남 | 약함 | 비모수적 |

면접에서는 신경망을 한쪽으로 단정하기보다 **형식(파라미터 수 고정)과 성격(가정이 거의 없음)을 나눠 말하는 것**이 정확하다.

### 이전 학습과의 연결

- [[2026-08-05-ai-data-bias-variance]] — 모수/비모수는 **편향-분산 축 위의 위치**다. 부스팅의 규제도 같은 손잡이를 돌리는 일이다.
- [[2026-08-19-ai-data-kmeans-vs-knn]] — KNN을 "파라미터가 없다"고 한 것은 KNN에 한해서는 맞다. 일반 정의는 **"파라미터 수가 데이터에 따라 늘어난다"** 다.
- [[2026-08-21-ai-data-gradient-boosting]] — 부스팅이 실무 기본값인 이유가 **규제된 비모수 모델**이라는 데서 설명된다.
- [[2026-08-13-ai-data-decision-tree]] — 트리가 **외삽을 못 하는** 이유는 구간을 나눠 평균을 외우는 구조 때문이다.
- [[2026-09-01-ai-data-svm]] — 선형 SVM은 모수적, **커널 SVM은 서포트 벡터 수가 데이터에 따라 정해져 비모수적**이다.
- [[2026-09-11-ai-data-cnn]] — 모수적 모델의 함수 형태 가정도 **귀납적 편향**이다. 데이터가 부족하면 이득, 넘치면 제약.
- [[2026-08-31-ai-data-hyperparameter-tuning]] — 부스팅의 깊이·학습률·조기 종료가 바로 **분산을 조절하는 하이퍼파라미터**다.
