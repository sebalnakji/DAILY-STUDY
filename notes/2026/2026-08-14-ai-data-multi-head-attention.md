## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 정의

**셀프 어텐션을 여러 벌(head) 병렬로 수행한 뒤, 결과를 이어붙여(concat) 하나로 합치는 구조.**

```text
입력 x
 ├─ head 1: Q₁,K₁,V₁ → Attention → 출력₁
 ├─ head 2: Q₂,K₂,V₂ → Attention → 출력₂
 ├─ ...
 └─ head h: Qₕ,Kₕ,Vₕ → Attention → 출력ₕ
                    ↓
        concat(출력₁...출력ₕ) · W_O → 최종 출력
```

- 각 헤드는 **자기만의 가중치 행렬** `W_Q, W_K, W_V`를 갖는다. → [[2026-08-06-ai-data-self-attention]]
- 합친 뒤 **출력 투영 행렬 `W_O`** 를 한 번 더 곱해 원래 차원으로 되돌린다.

### 왜 헤드를 여러 개 쓰는가

**하나의 어텐션은 한 종류의 관계만 포착한다.**

softmax는 **주목을 한 곳으로 몰아주는** 성질이 있어, 단일 헤드는 **하나의 패턴에 집중**하게 된다. 그런데 언어에는 동시에 봐야 할 관계가 여럿이다.

```text
"그 남자가 어제 산 책은 재미있었다"

문법 관계: 책 ← 산 (무엇을 샀나)
지시 관계: 그 남자 ← 남자
시간 관계: 산 ← 어제
주술 관계: 책 ← 재미있었다
```

**여러 헤드가 각각 다른 측면을 담당**해, 한 번에 여러 관계를 포착할 수 있다.

### 차원은 늘지 않는다 (중요)

헤드를 `h`개로 나눌 때, 각 헤드의 차원은 `d_model / h`로 **쪼갠다.**

```text
d_model = 512, h = 8  →  각 헤드는 64차원
concat 후 8 × 64 = 512  →  원래 차원 복귀
```

> **계산량은 단일 헤드와 거의 같다.** 넓은 공간 하나를 보는 대신 **좁은 공간 여럿을 보는** 것이다.

### 왜 나눠도 되는가

- 512차원 하나로 **모든 관계를 뭉뚱그려** 표현하는 것보다,
- 64차원짜리 **전문화된 표현 8개**를 갖는 편이 표현력이 좋다.

**앙상블과 같은 발상**이다 — 하나의 강한 모델보다 **다양한 관점 여럿의 조합**이 낫다. → [[2026-08-13-ai-data-decision-tree]]

### 실제로 헤드는 무엇을 학습하나

해석 연구에서 관찰된 예시들:

- **인접 토큰**에 주목하는 헤드
- **구문 의존 관계**(동사↔목적어)를 잡는 헤드
- **대명사의 지시 대상**(coreference)을 찾는 헤드
- 특정 **구분자·문장 끝** 토큰에 주목하는 헤드

다만 **모든 헤드가 해석 가능한 역할을 갖는 것은 아니다.** 상당수는 중복이거나 역할이 불분명하며, 일부를 제거해도 성능이 크게 떨어지지 않는다는 연구도 있다(head pruning).

### 파생 구조 — MHA → MQA → GQA

추론 시 **KV 캐시** 메모리를 줄이기 위해 헤드 구조를 변형한다.

| | Key/Value 헤드 | 특징 |
|---|---|---|
| **MHA** (Multi-Head Attention) | 쿼리 헤드마다 **각각** | 원래 방식. 품질 좋음, KV 캐시 큼 |
| **MQA** (Multi-Query Attention) | **전체가 1개 공유** | KV 캐시 최소, 품질 저하 가능 |
| **GQA** (Grouped-Query Attention) | **그룹당 1개** | 둘의 절충. LLaMA 등이 채택 |

**Query 헤드는 그대로 두고 Key/Value 헤드만 줄이는** 것이 핵심이다.

## 기준 답변

> ⚠️ 이 기준 레포는 질문에 대해 텍스트 답변 대신 외부 글 링크를 제공한다. 아래는 표준적인 Transformer 개념을 바탕으로 재구성한 답변이다.

**멀티헤드 어텐션은 셀프 어텐션을 여러 벌 병렬로 수행한 뒤 결과를 이어붙여 합치는 구조**다. 각 헤드는 자기만의 `W_Q`, `W_K`, `W_V` 가중치를 가지므로 서로 다른 방식으로 Q·K·V를 만든다. 합친 결과에 출력 투영 행렬 `W_O`를 곱해 원래 차원으로 되돌린다.

**헤드를 여러 개 쓰는 이유는 하나의 어텐션이 한 종류의 관계만 포착하기 때문**이다. softmax는 주목을 한 곳으로 몰아주므로 단일 헤드는 하나의 패턴에 집중하게 되는데, 언어에는 문법 관계, 지시 관계, 시간 관계 등 동시에 봐야 할 관계가 여럿이다. 여러 헤드가 각각 다른 측면을 담당하면 한 번에 여러 관계를 포착할 수 있다.

중요한 점은 **차원이 늘지 않는다**는 것이다. `d_model`을 헤드 수로 나눠 각 헤드가 `d_model / h` 차원을 담당하고, concat하면 원래 차원으로 돌아온다. 따라서 **계산량은 단일 헤드와 거의 같으며**, 넓은 공간 하나를 보는 대신 **좁은 공간 여럿을 보는** 구조다.

실제 해석 연구에서는 인접 토큰에 주목하는 헤드, 구문 의존 관계를 잡는 헤드, 대명사의 지시 대상을 찾는 헤드 등이 관찰된다. 다만 모든 헤드가 뚜렷한 역할을 갖는 것은 아니며, 일부를 제거해도 성능이 크게 떨어지지 않는 경우가 있다.

최근에는 추론 시 KV 캐시 메모리를 줄이기 위해 **MQA**(Key/Value 헤드를 하나만 공유)나 **GQA**(그룹당 하나 공유) 같은 변형을 사용한다.

## 내가 정리한 내용

**1. 멀티헤드 어텐션이란?**

**셀프 어텐션 여러 개를 병렬로 돌리고, 결과를 이어붙이는(concat) 구조**다. 각 헤드는 **자기만의 `W_Q`, `W_K`, `W_V` 가중치**를 가지므로, 같은 입력을 받아도 서로 다른 Q·K·V를 만들어 다른 것을 본다. 이어붙인 결과에 **출력 투영 행렬 `W_O`** 를 곱해 원래 차원으로 되돌린다.

**2. 왜 헤드를 여러 개 쓰는가**

**softmax가 주목을 한 곳으로 몰아주므로 단일 헤드는 하나의 패턴에만 집중**하게 된다. 그런데 언어에는 문법 관계, 지시 관계, 시간 관계처럼 **동시에 봐야 할 관계가 여럿**이다.

모델의 모든 차원을 하나로 써서 관계를 표현하는 것보다, **여러 개로 나누어 전문화된 관계 표현을 갖는 것이 표현력에서 더 좋다.** 각 헤드가 서로 다른 측면을 담당하기 때문이다.

**3. 헤드를 늘리면 계산량은?**

**거의 동일하다.** 헤드를 `h`개로 늘릴 때 각 헤드가 `d_model / h` 차원을 담당하도록 **차원을 나눠 갖기** 때문이다. 예를 들어 `d_model=512`에 헤드 8개면 각 헤드는 64차원이고, concat하면 다시 512차원이 된다.

즉 **넓은 공간 하나를 보는 대신 좁은 공간 여럿을 보는** 구조이며, 추가 비용 없이 다양성을 얻는다.

## 검토 결과

### 확인된 부분

- **"차원을 나눠 가지므로 계산량이 거의 같다"** 는 핵심을 정확히 파악. 멀티헤드에서 가장 오해하기 쉬운 지점을 정확히 짚었다.
- **표현력** 관점에서 여러 헤드의 이점을 설명함. "전문화된 관계 표현"이라는 표현이 정확하다.
- 실습 Q2에서 랜덤 포레스트와의 유사성(다양성의 조합)을 스스로 연결함.

### 보강 포인트

- **각 헤드가 왜 서로 다른지**를 명시할 것 — **헤드마다 자기만의 `W_Q`, `W_K`, `W_V`** 를 갖기 때문이다. 그리고 concat 후 **`W_O` 투영**으로 원래 차원에 복귀한다.
- **"왜 하나로는 부족한가"의 이유는 softmax다.** softmax가 주목을 한 곳으로 몰아주므로 단일 헤드는 한 패턴에만 집중한다.

### 심화: 랜덤 포레스트와의 비유 — 경계까지 알기 (Q2)

**공통점**: 다양성을 확보한 뒤 조합한다.

**그러나 결정적으로 다르다.**

| | 랜덤 포레스트 | 멀티헤드 어텐션 |
|---|---|---|
| 각자 하는 일 | **같은 문제**를 각자 풀어봄 | **다른 측면**을 나눠 맡음 |
| 합치는 법 | **평균(average)** | **연결(concat) + 투영** |
| 얻는 것 | **분산 감소**(통계적) | **표현력 확대** |
| 관계 | 서로 **독립적으로 학습** | **함께 학습**되며 역할이 갈림 |

**랜덤 포레스트**는 트리 100개가 전부 **같은 답**(이탈/유지)을 내고 그것을 **평균 내서** 흔들림을 줄인다.

**멀티헤드**는 헤드들이 **다른 답**을 낸다. 하나는 문법, 하나는 지시 관계를 본다. 평균 내면 오히려 **정보가 뭉개지므로** 이어붙여 전부 보존한다.

> **랜덤 포레스트는 "같은 걸 여러 번 봐서 확신을 얻고", 멀티헤드는 "다른 걸 나눠 봐서 시야를 넓힌다."**

⚠️ **따라서 "편향과 분산을 줄인다"는 표현은 조정이 필요하다.**
- **랜덤 포레스트(배깅)** = **분산** 감소 (편향은 오히려 살짝 증가)
- **멀티헤드** = 편향·분산이 아니라 **표현력(capacity)** 의 문제

→ 어제 배운 구분과 동일: **배깅은 분산, 부스팅은 편향.** [[2026-08-13-ai-data-decision-tree]]

**면접용 정리**
> *"둘 다 다양성을 조합하지만, 랜덤 포레스트는 같은 목표를 평균 내 분산을 줄이는 앙상블이고, 멀티헤드는 서로 다른 관계를 나눠 맡아 표현력을 넓히는 층 내부 구조입니다."*

**비유를 쓰되 경계를 아는 것**이 깊이로 읽힌다.

### 왜 여러 관계를 동시에 봐야 하나

```text
"그 남자가 어제 산 책은 재미있었다"

문법 관계: 책 ← 산 (무엇을 샀나)
지시 관계: 그 남자 ← 남자
시간 관계: 산 ← 어제
주술 관계: 책 ← 재미있었다
```

**하나의 어텐션으로는 이 중 하나만 잡는다.** 8개 헤드가 각각 다른 관계를 담당하면 한 번에 다 볼 수 있다.

### 실제로 헤드가 학습하는 것 (해석 연구)

- **인접 토큰**에 주목하는 헤드
- **구문 의존 관계**(동사↔목적어)를 잡는 헤드
- **대명사의 지시 대상**(coreference)을 찾는 헤드
- 특정 **구분자·문장 끝** 토큰에 주목하는 헤드

⚠️ 다만 **모든 헤드가 해석 가능한 역할을 갖지는 않는다.** 상당수는 중복이며, **일부를 제거해도 성능이 크게 떨어지지 않는다**는 연구가 있다(head pruning).

### 현대적 변형 — MHA → MQA → GQA

추론 시 **KV 캐시** 메모리를 줄이기 위한 변형이다.

| | Key/Value 헤드 | 특징 |
|---|---|---|
| **MHA** (Multi-Head Attention) | 쿼리 헤드마다 **각각** | 원래 방식. 품질 좋음, **KV 캐시 큼** |
| **MQA** (Multi-Query Attention) | **전체가 1개 공유** | 캐시 최소, **품질 저하** 가능 |
| **GQA** (Grouped-Query Attention) | **그룹당 1개** | 절충. **LLaMA 등이 채택** |

**Query 헤드는 그대로 두고 Key/Value 헤드만 줄이는** 것이 핵심. 컨텍스트를 늘리려는 노력과 같은 맥락이다. → [[2026-08-11-ai-data-positional-encoding]]

### Transformer 3요소 완성

```text
셀프 어텐션(8/6) + 위치 인코딩(8/11) + 멀티헤드(8/14)
```

- **셀프 어텐션** — 토큰들이 서로를 참조해 문맥을 반영 → [[2026-08-06-ai-data-self-attention]]
- **위치 인코딩** — 어텐션이 잃어버린 순서를 주입 → [[2026-08-11-ai-data-positional-encoding]]
- **멀티헤드** — 하나의 어텐션이 못 잡는 여러 관계를 병렬로 포착
