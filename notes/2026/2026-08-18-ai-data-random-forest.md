## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 정의

**여러 결정 트리로 구성된, 회귀와 분류를 위한 머신러닝 기법.** 여러 모델을 조합해 하나의 예측 문제를 푸는 **앙상블(ensemble) 기법**의 한 종류다. → [[2026-08-13-ai-data-decision-tree]]

### 두 겹의 무작위성 ⭐

랜덤 포레스트는 **배깅(bagging) 알고리즘의 확장**이며, 무작위성을 **두 군데**에 넣는다.

| | 무엇을 무작위로 | 방식 | 효과 |
|---|---|---|---|
| **① 배깅** | **데이터 샘플** | 학습 데이터에서 **복원 추출**(with replacement)로 무작위 표본 | **분산 감소** |
| **② 특징 샘플링** | **분기 후보 특징** | 분기를 고려할 때마다 전체 `n`개 중 `m`개를 **비복원 추출**(without replacement). 예: `m = √n` | **트리 간 상관 제거(decorrelate)** |

> **원문의 핵심 문장**
> - 무작위 데이터 표본으로 트리를 학습시키면 **분산이 줄어든다.**
> - 각 분기마다 특징을 샘플링하면 **트리들의 상관관계가 사라진다.**

**②가 랜덤 포레스트의 진짜 발명이다.** 배깅만 하면 **강한 특징 하나가 모든 트리의 최상단**을 차지해 트리들이 여전히 닮게 된다. 특징을 무작위로 제한하면 **강제로 다양해진다.**

### 주요 파라미터

| 파라미터 | 의미 |
|---|---|
| `max_depth` | 루트에서 리프까지의 **최장 경로** |
| `min_sample_split` | 노드를 분할하는 데 필요한 **최소 관측치 수** |
| `max_leaf_nodes` | 트리 분할을 제한해 **성장 억제** |
| `min_samples_leaf` | **리프 노드의 최소 샘플 수** |
| `n_estimators` | **트리의 개수** |
| `max_sample` | 개별 트리에 주어지는 **원본 데이터의 비율** |
| `max_features` | 트리에 제공되는 **최대 특징 수 제한** |

### 트리 깊이는 어떻게 정하나

깊을수록 트리에서 더 많은 정보를 추출하지만 **한계가 있다.** 과적합에 방어적인 알고리즘이라도 **데이터의 노이즈를 복잡한 특징으로 학습해 과적합할 수 있다.**

**정해진 법칙은 없으며**, 문헌이 제안하는 요령은 다음과 같다.

- 트리의 **최대 깊이 제한**
- **테스트 노드 수 제한**
- 분할에 필요한 **노드의 최소 객체 수 제한**
- 결과 부분표본 중 하나라도 **임계값 미만이면 분할하지 않음**
- 적합도를 **충분히 개선하지 못하면 노드 확장 중단**

### 트리는 몇 개가 필요한가

- `n_estimators`로 조절하며, **트리 수를 늘리면 과적합이 줄어든다.**
- **고정된 법칙은 없고** 데이터에 맞춰 미세 조정한다.
- 보통 **특징 수 `n`의 제곱**에서 시작해 최적 결과가 나올 때까지 튜닝한다.

### 병렬화가 쉬운가 — **쉽다**

트리들이 **서로 독립적으로 학습**되므로 병렬화가 자연스럽다. R에서는 `multicombine` 파라미터를 `TRUE`로 설정해 병렬 계산을 수행할 수 있다.

```r
rf <- foreach(ntree=rep(25000, 6), .combine=randomForest::combine,
              .multicombine=TRUE, .packages='randomForest') %dopar% {
    randomForest(x, y, ntree=ntree)
}
```

### 크고 많은 트리의 잠재적 문제

- **과적합**: 크고 많은 트리는 모델을 지나치게 복잡하게 만들어 학습 데이터를 암기하고 일반화에 실패할 수 있다.
- **느린 예측 시간**: 트리가 늘수록 새 데이터에 대한 예측 시간이 느려진다. **실시간 예측이나 대용량 데이터에서 문제.**
- **메모리 소비**: 많은 메모리를 소비해 대용량 데이터나 제한된 하드웨어에서 문제가 된다.
- **해석 가능성 저하**: 모델이 어떻게 예측하는지, 어떤 특징이 중요한지 이해하기 어려워진다.
- **튜닝의 어려움**: 튜닝 과정이 더 복잡하고 계산 비용이 커진다.

> **트리 수는 기본적으로 크게 잡는 것이 아니라, 문제와 데이터에 맞춰 계산 비용과 성능의 트레이드오프로 정해야 한다.**

### 상관된 특징이 있으면

- 랜덤 포레스트는 각 트리를 만들 때 특징을 샘플링하므로, **상관된 특징에 담긴 정보가 다른 정보보다 두 배 더 뽑힐 가능성이 높다.**
- 일반적으로 상관된 특징을 추가하면 **선형적으로 같은 정보를 담고 있다는 뜻**이므로 **모델의 강건성이 떨어진다.**
- 학습할 때마다 모델이 **"같은 일을 하는" 특징 중 하나 또는 다른 하나를 고르게** 된다(분산 설명, 엔트로피 감소 등).

## 기준 답변

기준 레포의 답변을 바탕으로 핵심만 재구성한다.

**랜덤 포레스트는 많은 결정 트리로 구성된, 회귀와 분류를 위한 머신러닝 기법**이다. **앙상블 기법**이라는 더 큰 부류에 속하며, 여러 모델을 조합해 하나의 예측 문제를 푸는 방식이다.

**무작위성이 필요한 이유**는 다음과 같다. 랜덤 포레스트는 **배깅 알고리즘의 확장**으로, 학습 데이터셋에서 **복원 추출로 무작위 데이터 표본**을 뽑아 여러 모델을 학습시키고 예측을 평균한다. 여기에 더해 **트리에서 분기를 고려할 때마다 전체 `n`개 특징 중 `m`개를 비복원 추출**해 분기 후보로 사용한다(예: `m = √n`).

- **무작위 데이터 표본으로 트리를 학습시키면 분산이 줄어든다.**
- **각 분기마다 특징을 샘플링하면 트리들의 상관관계가 사라진다.**

**주요 파라미터**로는 `max_depth`, `min_sample_split`, `max_leaf_nodes`, `min_samples_leaf`, `n_estimators`, `max_sample`, `max_features`가 있다.

**트리 깊이**는 깊을수록 더 많은 정보를 추출하지만 한계가 있어, 과적합에 방어적인 알고리즘이라도 **노이즈를 학습해 과적합할 수 있다.** 정해진 법칙은 없고 최대 깊이 제한, 노드 최소 객체 수 제한 등의 요령을 쓴다.

**트리 개수**는 `n_estimators`로 조절하며 **늘릴수록 과적합이 줄어든다.** 고정 법칙은 없고 보통 특징 수의 제곱에서 시작해 튜닝한다.

**병렬화는 쉽다.** 트리들이 독립적으로 학습되기 때문이다.

**크고 많은 트리의 문제**는 과적합, 느린 예측 시간, 메모리 소비, 해석 가능성 저하, 튜닝의 어려움이다. 트리 수는 기본값으로 크게 잡지 말고 **계산 비용과 성능의 트레이드오프**로 정해야 한다.

**상관된 특징이 있으면** 그 정보가 다른 정보보다 **두 배 더 뽑힐 가능성이 높아지며**, 일반적으로 상관된 특징은 같은 정보를 담고 있어 **모델의 강건성을 떨어뜨린다.**

## 내가 정리한 내용

**1. 랜덤 포레스트란?**

**여러 결정 트리로 구성된 앙상블 기법**으로, **회귀와 분류 모두 가능**하다. 앙상블은 여러 모델을 조합해 하나의 예측 문제를 푸는 방식이며, 랜덤 포레스트는 **배깅(bagging) 알고리즘의 확장**이다.

**2. 두 가지 무작위성**

- **배깅** — 학습 데이터에서 **복원 추출**로 무작위 데이터 표본을 뽑아 각 트리를 학습시킨다. → **분산 감소**
- **특징 샘플링** — 분기를 고려할 때마다 전체 `n`개 특징 중 `m`개를 **비복원 추출**해 후보로 쓴다(예: `m = √n`). → **트리 간 상관 제거(decorrelate)**

상관 제거가 중요한 이유는, **상관된 추정치를 평균 내면 분산 감소에 바닥이 생기기** 때문이다. 트리를 아무리 늘려도 상관이 높으면 그 이상 줄지 않는다. 배깅이 없으면 특징 샘플링만으로는 부족하고, 특징 샘플링이 없으면 **강한 특징 하나가 모든 트리의 최상단을 차지해** 트리들이 닮아버린다. 둘이 함께 작동해야 한다.

**3. 트리 개수는 어떻게 정하는가**

**성능 곡선이 평평해지는 지점**에서 정한다. 트리를 늘리면 과적합은 줄지만 **수익 체감**이 뚜렷해, 어느 지점부터는 **비용만 늘고 성능은 그대로**다.

랜덤 포레스트는 부트스트랩에서 빠진 데이터로 **OOB(Out-of-Bag) 에러**를 측정할 수 있어, 별도 검증셋 없이도 이 지점을 관찰할 수 있다.

트리가 지나치게 많고 크면 **느린 예측 시간, 메모리 소비, 해석 가능성 저하, 튜닝의 어려움**이 발생하므로, **계산 비용과 성능의 트레이드오프**로 결정한다.

## 검토 결과

### 확인된 부분

- **두 가지 무작위성을 방식과 효과로 정확히 짝지음** — 배깅=분산 감소 / 특징 샘플링=상관 제거. 원문의 핵심 두 문장을 그대로 흡수했다.
- 실습 Q1에서 **"강한 특징이 모든 트리의 최상단을 차지한다"** 는 메커니즘을 스스로 설명함.
- 실습 Q2에서 트리를 무작정 늘리면 안 되는 이유를 **비용·해석·튜닝**으로 정확히 제시.

### 보강 포인트

- **상관 제거가 왜 중요한지**를 수식으로 이해하면 답이 단단해진다.

  ```text
  상관된 n개 추정치의 평균 분산 = ρσ² + (1−ρ)σ²/n
                                  ↑        ↑
                              안 없어짐   n이 커지면 0으로
  ```

  `ρ`는 트리 간 상관계수. **`n`을 아무리 키워도 `ρσ²`는 남는다.** 트리를 100만 개 만들어도 상관이 높으면 분산이 그 이상 안 줄어든다. **`ρ`가 분산 감소의 바닥을 정한다.**

  > **배깅은 `n`을 키우고, 특징 샘플링은 `ρ`를 낮춘다.** 둘 다 있어야 분산이 제대로 줄어든다.

  원문이 *"decorrelates trees"* 라고 콕 집어 쓴 이유가 이것 — **상관 제거가 목적 그 자체**다.

- **Q3 정리에서 트레이드오프가 누락 → 추가.** 실습에서는 정확히 말했으나 정리에 빠졌다.
- **OOB 에러**는 랜덤 포레스트만의 도구이므로 언급하면 이해도가 드러난다.

### 심화: OOB(Out-of-Bag) 에러

부트스트랩으로 샘플을 뽑으면 각 트리마다 **안 뽑힌 데이터가 약 37% 남는다.** 이것이 OOB다.

> **그 트리가 한 번도 안 본 데이터이므로 검증용으로 쓸 수 있다.**

```text
트리 수를 늘려가며 OOB 에러를 관찰
→ 더 이상 안 떨어지면 그만 늘린다
```

**별도 검증셋 없이도 성능을 추정**할 수 있다는 것이 랜덤 포레스트의 매력적인 부수 효과다. → [[2026-07-30-ai-data-validation]]의 교차검증 부담을 덜어준다.

### 트리를 늘려도 과적합이 늘지 않는 이유

보통 모델을 복잡하게 하면 과적합이 늘어나는데, **랜덤 포레스트는 트리를 늘려도 과적합이 늘지 않는다.** 각 트리가 **독립적으로 학습**되어 **평균만 안정될 뿐**이기 때문이다.

**대신 비용이 는다.** 그래서 성능이 아니라 **비용을 기준으로 멈추는 지점**을 정하게 된다.

⚠️ 단, **개별 트리가 너무 크면** 여전히 과적합한다. `max_depth` 등 개별 트리 제약은 별개로 필요하다.

### 파라미터 — 숲과 나무

| 파라미터 | 의미 | 계열 |
|---|---|---|
| `n_estimators` | **트리 개수** | 숲 |
| `max_features` | 분기 후보 **특징 수 제한** | 숲 (특징 샘플링) |
| `max_sample` | 각 트리가 받는 **데이터 비율** | 숲 (배깅) |
| `max_depth` | 최장 경로 | 나무 |
| `min_sample_split` | 분할 최소 관측치 | 나무 |
| `min_samples_leaf` | 리프 최소 샘플 | 나무 |
| `max_leaf_nodes` | 리프 수 제한 | 나무 |

**앞의 셋은 "숲"을, 뒤의 넷은 "각 나무"를 조절한다.** 뒤의 넷은 어제 배운 **가지치기 파라미터** 그대로다. → [[2026-08-13-ai-data-decision-tree]]

### 병렬화 — GBDT와의 결정적 차이

**트리들이 서로 독립적으로 학습**되므로 병렬화가 자연스럽다. 트리 1000개를 코어 8개에 나눠 던지면 된다.

> ⚠️ **부스팅(GBDT)은 이전 트리의 오차를 보고 다음 트리를 만들어 순차적일 수밖에 없다.** 이것이 랜덤 포레스트와 GBDT의 구조적 차이다.

### 상관된 특징이 있으면

> **상관된 특징에 담긴 정보가 다른 정보보다 두 배 더 뽑힐 가능성이 높다.**

`키(cm)`와 `키(inch)`가 둘 다 있으면 분기 후보를 뽑을 때 **"키"라는 정보가 두 번의 기회**를 갖는다. 결과적으로 그 정보가 **과대 대표**된다.

일반적으로 상관된 특징을 추가하면 **선형적으로 같은 정보를 담고 있다는 뜻**이므로 모델의 **강건성이 떨어진다.** 학습할 때마다 "같은 일을 하는" 특징 중 하나 또는 다른 하나를 고르게 된다.

→ L2 정규화에서 본 *"상관된 특징들이 계수를 나눠 갖는다"* 와 같은 뿌리. [[2026-08-12-ai-data-feature-selection]]

### 트리 깊이 정하는 요령 (원문)

깊을수록 더 많은 정보를 추출하지만 **한계가 있다.** 과적합에 방어적인 알고리즘이라도 **노이즈를 복잡한 특징으로 학습해 과적합할 수 있다.** 정해진 법칙은 없고 다음 요령을 쓴다.

- 트리의 **최대 깊이 제한**
- **테스트 노드 수 제한**
- 분할에 필요한 **노드의 최소 객체 수 제한**
- 결과 부분표본 중 하나라도 **임계값 미만이면 분할하지 않음**
- 적합도를 **충분히 개선하지 못하면 노드 확장 중단**
