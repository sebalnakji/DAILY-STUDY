# 머신러닝이란 무엇이며, 전통적인 프로그래밍과 무엇이 다른가?

## 질문

> **머신러닝이란 무엇이며, 전통적인 프로그래밍과 어떻게 다른가?**
>
> 원문: *What is machine learning and how does it differ from traditional programming?*

## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

- **전통적 프로그래밍**: 사람이 **규칙(로직)** 을 직접 작성한다. `데이터 + 규칙 → 답`
- **머신러닝**: 사람이 **데이터와 답**을 주면 기계가 **규칙을 찾아낸다**. `데이터 + 답 → 규칙`
  - 이 방향 전환이 이 질문의 핵심이다.
- **학습된 규칙 = 모델**: 코드로 명시되지 않고 **파라미터(가중치)** 형태로 존재한다.
- **일반화**: 학습 데이터가 아니라 **처음 보는 데이터**에서 잘 동작하는 것이 목표. → [[2026-07-20-ai-data-supervised-learning]]
- **결정론 vs 확률론**: 전통적 프로그램은 같은 입력에 항상 같은 답을 보장하지만, ML은 **확률적으로 맞히며 틀릴 수 있다**.
- **ML을 써야 하는 조건** (면접 판단 포인트)
  - 규칙이 너무 복잡하거나 사람이 언어로 명시하기 어렵다 (예: 고양이 사진 판별)
  - 규칙이 계속 변한다 (스팸 패턴, 사용자 취향)
  - 충분한 양의 **데이터가 있다**
- **ML을 쓰면 안 되는 경우**: 규칙이 명확하고 안정적이면 `if` 문이 더 정확하고 싸고 빠르다. (예: 세금 계산)
- **유지보수 방식의 차이**: 전통적 프로그래밍은 **코드를 고치고**, ML은 **데이터를 고치고 재학습**한다.

## 기준 답변

> ⚠️ 이 기준 레포는 질문 목록만 제공하고 답변은 싣지 않는다. 아래는 표준적인 ML 교재·강의 기준으로 재구성한 답변이다.

**머신러닝은 명시적으로 프로그래밍하지 않고, 데이터로부터 패턴을 학습해 예측이나 결정을 수행하는 기법**이다.

전통적인 프로그래밍과의 근본적인 차이는 **무엇을 사람이 주고 무엇을 기계가 만드는가**에 있다.

| | 사람이 주는 것 | 기계가 만드는 것 |
|---|---|---|
| 전통적 프로그래밍 | 데이터 + **규칙** | 답 |
| 머신러닝 | 데이터 + **답** | **규칙(모델)** |

전통적 프로그래밍에서는 개발자가 로직을 직접 작성하고, 프로그램은 그 로직을 그대로 실행한다. 반면 머신러닝에서는 입력과 정답의 쌍을 주면 알고리즘이 **둘을 잇는 규칙을 스스로 찾아내며**, 그 결과물이 모델이다.

따라서 머신러닝은 **규칙을 사람이 명시하기 어렵거나 계속 변하는 문제**에 적합하다. 반대로 규칙이 명확하고 안정적인 문제라면 전통적 프로그래밍이 더 정확하고 저렴하다.

## 내가 정리한 내용

**1. 머신러닝이란?**

규칙을 찾기 어려운 작업일 때, 입력 데이터와 결과 데이터를 학습시켜 **기계가 규칙을 스스로 찾게 하는 방법**이다. 전통적 프로그래밍이 `데이터 + 규칙 → 답`이라면, 머신러닝은 `데이터 + 답 → 규칙`으로 방향이 뒤집힌다.

**2. 전통적 프로그래밍과의 결정적 차이**

룰베이스는 **결정론적**이라 내가 정한 규칙을 100% 그대로 실행하고, ML은 데이터에서 찾은 규칙으로 **확률적인** 답을 내므로 틀릴 수 있다.

또한 룰베이스는 배포하면 계속 그대로 동작하지만, **ML은 코드를 안 고쳐도 데이터 드리프트로 성능이 저하되어** 모니터링과 재학습이 필요하다.

**3. 언제 무엇을 쓰는가**

- **룰베이스** — 규칙이 명확하고 안정적일 때, 100% 정확해야 할 때, 원인과 결과를 설명할 수 있어야 할 때.
- **ML** — 규칙이 복잡하거나 계속 변해 사람이 명시하기 어렵고, **학습할 데이터가 충분할 때.** 단, 예측 근거를 명확히 설명하기 어렵다는 점을 감수해야 한다.

## 검토 결과

### 확인된 부분

- 정의에 **"규칙을 찾기 어려운 작업일 때"** 라는 적용 조건까지 포함시킴. 정의와 판단 기준을 한 문장에 담은 좋은 답변.
- 실습 Q1(무료배송 5만원)에서 룰베이스를 선택하고 근거를 **"규칙을 찾는 작업이 아니기 때문"** 으로 제시. 이 질문의 판단 기준을 정확히 요약함.
- 실습 Q2에서 성능 저하 원인을 드리프트로 진단하고 재학습 필요성까지 연결함.
- **설명가능성(explainability)** 을 판단 기준으로 스스로 제시함. 실무에서 중요한 관점.

### 보강 포인트

- **용어**: 데이터 드래프트(draft) → **데이터 드리프트(drift)**. 개념은 정확했으나 표기를 교정.
- **"100%"의 의미를 분리할 것.** 룰베이스가 보장하는 것은 *정답률 100%* 가 아니라 **"내가 정한 규칙을 100% 그대로 실행한다"** 이다.
  - 무료배송: 규칙 자체가 정답의 정의 → 결과도 100% 정확
  - 룰베이스 스팸 필터: 규칙은 100% 충실히 실행되지만 정확도는 낮음
  - 따라서 정확한 대비 축은 **결정론적(deterministic) vs 확률적(probabilistic)** 이고, **정확도는 별개의 축**이다.
- **드리프트는 두 종류로 구분한다.**

  | 종류 | 무엇이 변하나 | 이탈 예측 예시 |
  |---|---|---|
  | 데이터 드리프트 | 입력 `X`의 분포 | 신규 고객층이 40대 → 20대로 이동 |
  | 컨셉 드리프트 | `X`와 `y`의 관계 | "주 3회 미접속"이 앱 개편 후 정상 패턴이 됨 |

  컨셉 드리프트가 더 위험하다. 입력 분포는 멀쩡해 보여서 모니터링에 안 잡히는데, 모델의 전제가 이미 무너진 상태다.
- **핵심 원리: ML 시스템은 코드를 안 고쳐도 저절로 썩는다.** 룰베이스 `if` 문은 5년 뒤에도 동일하게 동작하지만 ML은 세상이 변하면 성능이 떨어진다. 그래서 ML은 배포가 끝이 아니라 **모니터링 + 주기적 재학습**이 따라붙는다.
  - 이것이 Q1에서 룰베이스를 택해야 하는 더 깊은 이유다. 공짜로 끝날 `if` 문 자리에 **평생 유지보수할 살아있는 시스템**을 심는 셈이기 때문.
- **ML은 상관관계를 줄 뿐 인과관계를 주지 않는다.** 대출 심사·의료 진단 같은 규제 산업에서는 설명이 법적 의무여서, 성능이 좋아도 블랙박스 모델을 쓰지 못하는 경우가 있다.
- **ML의 전제조건은 데이터다.** 규칙이 아무리 복잡해도 학습할 데이터가 없으면 시작할 수 없다.

### 한 줄 원칙

> **규칙을 적을 수 있으면 적어라. 적을 수 없을 때 ML을 쓴다.**
