## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 출발점 — 어텐션의 진짜 병목은 연산이 아니다

[[2026-08-06-ai-data-self-attention]]에서 본 어텐션 계산은 이렇다.

```text
S = QKᵀ          (n × n 행렬)
P = softmax(S)   (n × n 행렬)
O = PV           (n × d 행렬)
```

여기서 흔히 **`O(n²)` 연산량**이 문제라고 말한다. 그런데 Flash Attention 논문의 관찰은 다르다.

> **GPU는 계산이 남아돈다. 병목은 데이터를 옮기는 일이다.**

### GPU 메모리 계층 — 두 종류의 메모리

| | **SRAM** (온칩) | **HBM** (고대역폭 메모리) |
|---|---|---|
| 위치 | 연산 유닛 **바로 옆** | 칩 **바깥** |
| 크기 (A100 기준) | 약 **20 MB** | **40~80 GB** |
| 대역폭 | 약 **19 TB/s** | 약 **1.5~2 TB/s** |
| 비유 | 책상 위 | 서가 |

**대역폭이 약 10배 차이**난다. 그리고 우리가 흔히 "GPU 메모리"라고 부르는 것은 **HBM**이다.

> 🏫 **비유**: 책상(SRAM)은 좁고 서가(HBM)는 넓다. 계산은 책상에서만 할 수 있다. **책을 서가에서 꺼내 오고 다시 꽂는 일**이 실제 작업보다 오래 걸린다면, 아무리 빨리 읽어도 소용이 없다.

### 표준 어텐션이 낭비하는 것

표준 구현은 중간 결과를 **매번 HBM에 쓰고 다시 읽는다.**

```text
① Q, K를 HBM에서 읽는다
② S = QKᵀ 계산  →  n×n 행렬을 HBM에 쓴다        ← 거대한 쓰기
③ S를 HBM에서 다시 읽는다                        ← 거대한 읽기
④ P = softmax(S)  →  n×n 행렬을 HBM에 쓴다      ← 또 쓰기
⑤ P를 다시 읽고, V도 읽는다                       ← 또 읽기
⑥ O = PV 계산  →  결과를 HBM에 쓴다
```

`n = 4096`이면 `n × n = 1,677만 개` 원소짜리 행렬이 **여러 번 왕복**한다.

| | 크기 |
|---|---|
| Q, K, V | `n × d` — 상대적으로 작다 |
| **S, P (어텐션 행렬)** | **`n × n`** — 시퀀스가 길어지면 압도적으로 크다 |

**연산 유닛은 데이터를 기다리며 놀고 있다.** 이런 상태를 **메모리 병목(memory-bound)** 이라고 한다 — [[2026-09-02-ai-data-kv-cache]]의 디코드 단계와 같은 상황이다.

### Flash Attention의 해법 — 세 가지 기법

#### ① 타일링(Tiling) — 블록으로 쪼개 책상 위에서 끝낸다

Q, K, V를 **SRAM에 들어갈 만한 블록**으로 쪼개고, 블록 단위로 계산을 끝낸 뒤 결과만 HBM에 쓴다.

```text
       K 블록들 →
     ┌────┬────┬────┐
  Q  │ 계산│ 계산│ 계산│   한 블록씩 SRAM에 올려
 블록 ├────┼────┼────┤   계산하고 결과를 누적
  들  │ 계산│ 계산│ 계산│
  ↓  └────┴────┴────┘

n×n 행렬 전체를 한 번도 만들지 않는다
```

#### ② 온라인 소프트맥스(Online Softmax) — 전체를 안 보고도 정규화한다

타일링에는 걸림돌이 있다. **소프트맥스는 행 전체의 합이 필요하다.** 블록별로 쪼개면 전체 합을 어떻게 아나?

**해법**: 지금까지 본 **최댓값과 합을 기억해 두고, 새 블록을 볼 때마다 갱신**한다.

```text
블록 1을 보고  →  running max, running sum 기록, 부분 출력 계산
블록 2을 보고  →  새 최댓값이 나오면 이전 결과를 비율에 맞춰 보정하고 누적
블록 3을 보고  →  또 보정하고 누적
...
→ 마지막에 전체를 한 번에 계산한 것과 정확히 같은 값
```

**근사가 아니다.** 순서를 바꿔도 결과가 같도록 수학적으로 보정한다.

#### ③ 재계산(Recomputation) — 역전파용 저장을 안 한다

[[2026-09-04-ai-data-backpropagation]]에서 본 대로, 역전파를 하려면 순전파의 중간값이 필요하다. 어텐션 행렬 `P`를 저장하면 또 `O(n²)` 메모리다.

**Flash Attention은 저장하지 않고, 역전파 때 SRAM에서 다시 계산한다.**

> 💡 이건 그 노트에서 다룬 **그래디언트 체크포인팅과 정확히 같은 트릭**이다 — **메모리를 아끼려 연산을 더 쓴다.**

## 기준 답변

### 결과 — 무엇이 달라지나

| 항목 | 표준 어텐션 | **Flash Attention** |
|---|---|---|
| **결과값** | 기준 | **정확히 동일** (근사 아님) |
| **메모리** | `O(n²)` | **`O(n)`** |
| **HBM 접근량** | 많다 | **크게 감소** |
| **속도** | 기준 | **2~4배 빠름** |
| **연산량(FLOPs)** | 기준 | **오히려 약간 증가** (재계산 때문) |

**마지막 줄이 이 기법의 성격을 말해 준다.**

### 흔한 오해 — "계산량을 줄인다"가 아니다

> ❌ Flash Attention은 어텐션의 `O(n²)` 연산량을 줄인다
> ✅ Flash Attention은 **연산량을 그대로 두고 메모리 이동을 줄인다**

```text
어텐션의 연산량   : O(n²)  →  O(n²)   그대로
어텐션의 메모리   : O(n²)  →  O(n)    크게 감소
HBM 읽기·쓰기    : 많음    →  적음    ← 여기가 진짜 이득
실제 속도        : 2~4배 빨라짐
```

**연산을 줄이지 않았는데 빨라진다**는 게 핵심이다. 병목이 연산이 아니었기 때문이다.

> ⚠️ 그래서 Flash Attention을 **희소 어텐션(sparse attention)과 같은 줄에 놓으면 안 된다.**
>
> | | 무엇을 하나 | 결과 |
> |---|---|---|
> | **희소 어텐션** | 일부 토큰 쌍을 **아예 계산하지 않는다** | **근사** — 결과가 달라진다 |
> | **Flash Attention** | 전부 계산하되 **메모리 이동을 줄인다** | **정확** — 결과가 같다 |
>
> 희소 어텐션은 **정확도를 내주고 연산을 산다.** Flash Attention은 **아무것도 내주지 않는다** — 그래서 사실상 **공짜 개선**이고, PyTorch 등에 기본 탑재됐다.

### 왜 "I/O 인식(IO-Aware)"인가

논문 제목의 핵심어다. 기존 어텐션 구현은 **연산 횟수만 세고 메모리 이동은 세지 않았다.** Flash Attention은 **하드웨어 메모리 계층을 알고리즘 설계에 반영**했다.

```text
기존 사고 : "연산을 줄이면 빨라진다"
IO 인식   : "어느 메모리에서 얼마나 옮기는지가 속도를 정한다"
```

**같은 수학, 다른 실행 순서.** 알고리즘을 바꾼 게 아니라 **하드웨어에 맞춰 계산 순서를 재배치**한 것이다.

### 한 문장 요약

> **Flash Attention은 어텐션을 근사 없이 정확히 계산하면서, `n×n` 행렬을 HBM에 한 번도 만들지 않도록 타일링·온라인 소프트맥스·재계산을 조합한 I/O 인식 알고리즘이다. 연산량은 그대로지만 메모리 이동이 줄어 2~4배 빨라진다.**

## 내가 정리한 내용

### 1. 어텐션의 진짜 병목

- **데이터를 읽고 쓰기 위해 왕복하는 것이 진정한 병목이다.**
- 어떻게 아는가 — **Flash Attention에서 계산은 약간 늘었는데 속도는 2~4배 빨라졌다.**

```text
재계산으로 FLOPs가 증가했는데도 빨라졌다
  → 연산이 병목이었다면 느려져야 했다
  → 느려지지 않았다는 건 연산 유닛에 여유가 있었다는 뜻
```

**연산 유닛이 데이터를 기다리며 놀고 있었기 때문에**, 그 빈 시간에 재계산을 끼워 넣어도 전체 시간이 안 늘어난다.

> 💡 뒤집으면 판단 기준이 된다 — **연산을 줄였는데 안 빨라지면 그건 연산 병목이 아니다.**

### 2. 세 가지 기법

- **타일링(Tiling)** — 데이터를 블록으로 쪼개서 SRAM에 올려 계산하고 결과를 누적한다. `n×n` 행렬 전체를 한 번도 만들지 않는다.
- **온라인 소프트맥스(Online Softmax)** — 최댓값과 합을 기억해 두고 새 블록마다 갱신한다. 새 최댓값이 나오면 이전 결과를 비율에 맞춰 보정한다.
- **재계산(Recomputation)** — 역전파용으로 어텐션 행렬을 **저장하지 않고**, 역전파 때 SRAM에서 **다시 계산**한다. 저장하면 또 `O(n²)` 메모리이기 때문이다.

**왜 하필 최댓값을 기억하나** — 소프트맥스의 **수치 안정성** 때문이다.

```text
exp(1000) = 오버플로 → 그래서 표준 구현은 최댓값을 빼고 계산한다
  softmax(xᵢ) = exp(xᵢ − max) / Σ exp(xⱼ − max)

블록마다 최댓값이 다르므로, 새 최댓값이 나오면
  이전 부분합 × exp(이전 max − 새 max)  로 새 기준에 환산
              └────────────────────┘
        "비율에 맞춰 보정"의 실체
```

이 보정이 정확하기 때문에 **근사가 아니라 완전히 동일한 값**이 나온다.

### 3. 결과

**연산량이 약간 증가한 대신 메모리는 적어졌고, 속도는 빨라졌는데 결과는 정확히 같다.**

| 항목 | 표준 어텐션 | Flash Attention |
|---|---|---|
| 결과값 | 기준 | **정확히 동일** (근사 아님) |
| 메모리 | `O(n²)` | **`O(n)`** |
| 속도 | 기준 | **2~4배 빠름** |
| 연산량(FLOPs) | 기준 | **약간 증가** (재계산) |

### 4. 희소 어텐션과의 차이

- **희소 어텐션**은 **정확도를 내주는 대신 연산량 감소**를 얻는다. 일부 토큰 쌍을 아예 계산하지 않으므로 결과가 달라진다.
- **Flash Attention**은 **내주는 것이 없는데 메모리 감소와 속도 증가**를 얻는다. 전부 계산하되 메모리 이동만 줄이므로 결과가 같다.

**"아무것도 안 내준다"를 정확히 하면**

| 관점 | 내주는 것 |
|---|---|
| **모델 품질** | 없음 — 수학적으로 동일 |
| **연산량** | **약간 증가** (재계산) |
| **구현 복잡도** | **크다** — 커스텀 CUDA 커널을 직접 짜야 한다 |

**사용자 입장에서는 공짜지만 구현자 입장에서는 아니다.** 그래서 라이브러리에 내장되는 방식으로 보급됐다 — 한 명이 어렵게 짜면 모두가 공짜로 쓴다.

> 💡 두 기법은 **배타적이지 않다.** 희소 어텐션을 Flash Attention 방식으로 구현할 수도 있다. 하나는 **무엇을 계산할지**를 줄이고, 다른 하나는 **어떻게 계산할지**를 바꾸기 때문이다.

## 검토 결과

### 확인된 부분

- **주장에 근거를 붙였다** — "메모리가 병목이다"만이 아니라 **"재계산으로 연산이 늘었는데도 빨라졌다"** 는 증거를 함께 들었다. 면접에서 이 한 줄이 이해 여부를 가른다.
- **결과 네 가지**(연산량↑, 메모리↓, 속도↑, 결과 동일)를 빠짐없이 담았다. 특히 **"결과는 정확히 같다"** 를 빼먹지 않은 것이 중요하다 — 이게 희소 어텐션과 갈리는 지점이다.
- **희소 어텐션과의 대비에서 양쪽을 다** 답했다(내주는 것 / 얻는 것).
- **항목에 설명을 붙였다** — 타일링과 온라인 소프트맥스에 각각 한 줄씩. 지난 세 번(CNN·드롭아웃·전이학습) 지적됐던 **"이름만 나열"** 패턴이 고쳐진 지점이다.

### 보강 포인트

#### ① 세 기법 중 **재계산**이 빠졌다

| | 내용 |
|---|---|
| **전** | 타일링, 온라인 소프트맥스 (2개) |
| **후** | + **재계산(Recomputation)** (위 `내가 정리한 내용` 2번) |

**이 세 번째가 1번에서 든 근거의 출처다.** "연산이 약간 늘었다"가 바로 재계산 때문인데, 1번에서는 그 사실을 쓰고 2번 목록에서는 빠뜨렸다. **자기 답변 안에서 앞뒤가 연결되는지 확인하는 습관**이 필요하다.

#### ② "왜 하필 최댓값인지"가 빠졌다

**소프트맥스의 수치 안정성** 때문이다. 교정 후 내용은 위 `내가 정리한 내용` 2번에 반영.

### 심화: "연산이 병목이 아니다"를 증명하는 법

```text
Flash Attention은 역전파용 어텐션 행렬을 저장하지 않고 다시 계산한다
  → FLOPs가 증가한다
  → 그런데도 2~4배 빨라진다

연산이 병목이었다면 연산을 늘렸으니 느려져야 했다
느려지지 않았다는 건 → 연산 유닛에 여유가 있었다는 뜻
```

**이것이 최적화 지점을 찾는 일반적 사고다.** 어디를 고쳐야 할지 모를 때, **한쪽을 일부러 늘려 보고 전체가 느려지는지** 보면 그게 병목인지 알 수 있다.

### 심화: GPU 메모리 계층

| | **SRAM** (온칩) | **HBM** (고대역폭 메모리) |
|---|---|---|
| 위치 | 연산 유닛 **바로 옆** | 칩 **바깥** |
| 크기 (A100 기준) | 약 **20 MB** | **40~80 GB** |
| 대역폭 | 약 **19 TB/s** | 약 **1.5~2 TB/s** |
| 비유 | 책상 위 | 서가 |

**대역폭이 약 10배 차이**나고, 우리가 "GPU 메모리"라 부르는 것은 **HBM**이다.

> 🏫 책상(SRAM)은 좁고 서가(HBM)는 넓다. 계산은 책상에서만 할 수 있다. **책을 꺼내 오고 다시 꽂는 일**이 실제 읽기보다 오래 걸린다면 아무리 빨리 읽어도 소용없다.

**표준 어텐션이 낭비하는 것**

```text
① Q, K를 HBM에서 읽는다
② S = QKᵀ 계산  →  n×n 행렬을 HBM에 쓴다        ← 거대한 쓰기
③ S를 HBM에서 다시 읽는다                        ← 거대한 읽기
④ P = softmax(S)  →  n×n 행렬을 HBM에 쓴다      ← 또 쓰기
⑤ P를 다시 읽고, V도 읽는다                       ← 또 읽기
⑥ O = PV 계산  →  결과를 HBM에 쓴다
```

`n = 4096`이면 `n × n = 1,677만 개` 원소짜리 행렬이 **여러 번 왕복**한다.

### 심화: "I/O 인식(IO-Aware)"의 뜻

논문 제목의 핵심어다. 기존 어텐션 구현은 **연산 횟수만 세고 메모리 이동은 세지 않았다.** Flash Attention은 **하드웨어 메모리 계층을 알고리즘 설계에 반영**했다.

```text
기존 사고 : "연산을 줄이면 빨라진다"
IO 인식   : "어느 메모리에서 얼마나 옮기는지가 속도를 정한다"
```

**같은 수학, 다른 실행 순서.** 알고리즘을 바꾼 게 아니라 **하드웨어에 맞춰 계산 순서를 재배치**한 것이다.

### 심화: 기존 노트 교정 필요

[[2026-08-11-ai-data-positional-encoding]]과 [[2026-08-20-ai-data-context-window]]에서 Flash Attention을 **"계산량을 줄이는 기법"** 으로 적고 희소 어텐션과 같은 줄에 놓았다. **이는 정확하지 않다.**

| | 당시 표현 | 정확한 표현 |
|---|---|---|
| 08-11 | `O(n²) 계산량` 문제의 완화책 → Flash Attention, 희소 어텐션 | Flash Attention은 **계산량을 줄이지 않는다.** 메모리 이동을 줄여 **같은 계산을 더 빨리** 한다 |
| 08-20 | "계산량을 줄이는 Flash Attention·희소 어텐션" | 같음 |

**다음 복습 때 두 노트에 교정을 반영할 것.**

### 이전 학습과의 연결

- [[2026-08-06-ai-data-self-attention]] — `S = QKᵀ → softmax → ×V` 세 단계가 오늘의 출발점이다. **어느 중간 결과가 `n×n`인지**를 알아야 병목이 보인다.
- [[2026-09-02-ai-data-kv-cache]] — **메모리 병목(memory-bound)** 이라는 같은 진단. 디코드 단계도 연산 유닛이 놀고 메모리 대역폭이 병목이었다.
- [[2026-09-04-ai-data-backpropagation]] — **그래디언트 체크포인팅과 재계산이 같은 트릭**이다. 메모리를 아끼려 연산을 더 쓴다.
- [[2026-09-15-ai-data-mixture-of-experts]] — **연산 ↔ 메모리 축** 위의 또 다른 이동. MoE는 메모리를 내주고 연산을 샀고, Flash Attention은 연산을 조금 내주고 메모리를 샀다.
- [[2026-08-20-ai-data-context-window]] · [[2026-08-11-ai-data-positional-encoding]] — 두 노트의 **Flash Attention 서술에 교정이 필요**하다(위 심화 절 참고).
- [[2026-08-19-backend-latency-numbers]] — **메모리 계층마다 속도가 자릿수로 다르다**는 사고가 GPU 내부(SRAM vs HBM)에서 그대로 반복된다.
