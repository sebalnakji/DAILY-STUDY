## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 왜 필요한가 — 임베딩만으로는 부족하다

임베딩은 토큰마다 벡터를 준다. 그런데 **같은 단어라도 문맥에 따라 뜻이 달라진다.** → [[2026-08-03-ai-data-embeddings]]의 문맥 임베딩

```text
"배가 고프다"  vs  "배를 타다"
```

**셀프 어텐션은 문장 안의 다른 토큰들을 참고해 각 토큰의 벡터를 문맥에 맞게 갱신하는 장치**다. 즉 **정적 임베딩 → 문맥 임베딩**으로 바꾸는 메커니즘.

### 정의

**셀프 어텐션은 한 문장(시퀀스) 안의 모든 토큰이 서로를 참조해, 각 토큰이 "어디에 주목할지"를 학습하는 연산이다.**

- "셀프(self)"인 이유: 다른 문장이 아니라 **자기 자신의 시퀀스** 안에서 참조하기 때문.
- 참조 대상이 다른 시퀀스면 **크로스 어텐션(cross-attention)** 이라 부른다.

### Q, K, V — 검색에 비유하면 명확하다

각 토큰의 입력 벡터에 **서로 다른 가중치 행렬**을 곱해 세 가지 벡터를 만든다.

| | 이름 | 역할 | 검색 비유 |
|---|---|---|---|
| **Q** | Query(질의) | **내가 찾는 것** | 검색창에 입력한 검색어 |
| **K** | Key(키) | **내가 가진 표지** | 문서의 제목·태그 |
| **V** | Value(값) | **실제로 전달할 내용** | 문서의 본문 |

```text
입력 벡터 x  →  Q = x·W_Q,  K = x·W_K,  V = x·W_V
                (W_Q, W_K, W_V 는 학습되는 가중치 행렬)
```

**핵심: 어떤 토큰과 관련 있는지는 Q와 K로 정하고, 실제로 가져오는 정보는 V다.** 관련도 판단과 전달 내용이 분리되어 있다.

### 계산 4단계

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

1. **점수 계산**: `Q · Kᵀ` — 내 Query와 모든 토큰의 Key를 내적해 **관련도 점수**를 얻는다.
2. **스케일링**: `÷ √d_k` — 차원이 커질수록 내적값이 커져 softmax가 극단으로 쏠리는(기울기 소실) 것을 막는다.
3. **정규화**: `softmax` — 점수를 합이 1인 **가중치(주목 비율)** 로 바꾼다.
4. **가중합**: `× V` — 그 비율로 각 토큰의 Value를 섞어 **새로운 문맥 반영 벡터**를 만든다.

### 왜 √d_k로 나누나

내적은 차원 수가 커질수록 값의 분산이 커진다. 값이 너무 크면 softmax 결과가 **한 곳에 1, 나머지는 0**에 가깝게 극단화되고, 그러면 **기울기가 거의 0이 되어 학습이 안 된다.** `√d_k`로 나누면 분산이 적절히 유지된다.

### 멀티헤드 어텐션(Multi-Head Attention)

- 어텐션을 **여러 벌(head) 병렬로** 수행한 뒤 결과를 합친다.
- 이유: 하나의 어텐션은 **한 종류의 관계**만 포착한다. 여러 헤드가 각각 문법 관계, 지시 관계, 의미 관계 등 **서로 다른 측면**을 담당할 수 있다.

### 인과 마스킹(Causal Masking)

- GPT 같은 **디코더 계열**은 다음 토큰을 예측해야 하므로 **미래 토큰을 보면 안 된다.**
- 그래서 현재 위치보다 뒤에 있는 토큰의 점수를 `-∞`로 만들어 softmax 후 0이 되게 한다.
- → [[2026-07-22-ai-data-what-is-an-llm]]의 자기회귀 생성과 직결.

### 위치 정보 문제 (Positional Encoding)

셀프 어텐션은 **순서를 모른다.** 모든 토큰을 동시에 보기 때문에 `"철수가 영희를 좋아한다"`와 `"영희가 철수를 좋아한다"`를 구분할 수 없다. 그래서 입력에 **위치 인코딩(positional encoding)** 을 더해 순서 정보를 주입한다.

### 대가 — 계산 복잡도 O(n²)

모든 토큰이 모든 토큰을 참조하므로 **토큰 수 `n`의 제곱에 비례**해 계산·메모리가 늘어난다. **컨텍스트 윈도우가 무한정 길어지지 못하는 근본 이유**다.

## 기준 답변

> ⚠️ 이 기준 레포는 질문에 대해 텍스트 답변 대신 외부 글 링크를 제공한다. 아래는 표준적인 Transformer 개념을 바탕으로 재구성한 답변이다.

**셀프 어텐션은 시퀀스 안의 각 토큰이 같은 시퀀스의 다른 모든 토큰을 참조해, 문맥에 맞게 자신의 표현을 갱신하는 연산**이다.

각 토큰의 임베딩에 학습된 세 개의 가중치 행렬을 곱해 **Query, Key, Value** 벡터를 만든다. Query는 "내가 무엇을 찾는가", Key는 "나는 무엇을 가지고 있는가", Value는 "실제로 전달할 내용"에 해당한다.

계산은 다음과 같다.

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

Query와 모든 Key를 내적해 관련도 점수를 구하고, `√d_k`로 나누어 스케일을 조정한 뒤, softmax로 합이 1인 가중치를 만든다. 그 가중치로 Value들을 가중합하면 **문맥이 반영된 새로운 벡터**가 된다.

`√d_k`로 나누는 이유는, 차원이 커지면 내적값의 분산이 커져 softmax가 극단으로 쏠리고 **기울기가 소실되기 때문**이다.

실제 Transformer는 이 연산을 여러 벌 병렬로 수행하는 **멀티헤드 어텐션**을 사용해, 각 헤드가 서로 다른 종류의 관계를 포착하게 한다. GPT 같은 디코더 모델은 미래 토큰을 보지 못하도록 **인과 마스킹**을 적용한다.

셀프 어텐션은 순서를 모르기 때문에 **위치 인코딩**으로 순서 정보를 주입해야 하며, 모든 토큰 쌍을 계산하므로 **복잡도가 O(n²)** 이라는 대가가 있다.

## 내가 정리한 내용

**1. 셀프 어텐션이란?**

**주변 토큰들을 참고해 각 토큰의 벡터를 문맥에 맞게 갱신하는 연산.** 예를 들어 동음이의어가 있을 때 문맥을 참고해 알맞은 의미의 벡터로 이동시킨다. 같은 시퀀스 안에서 서로를 참조하기 때문에 "셀프"라고 부른다.

**2. Q, K, V**

**문장 안의 모든 토큰이 각각 Q, K, V를 전부 가진다.** 토큰의 임베딩에 학습된 세 가중치 행렬을 곱해 만든다.

- **Q(Query)** — 이 토큰이 **무엇을 찾는가**
- **K(Key)** — 이 토큰이 **어떻게 찾히는가** (표지)
- **V(Value)** — 이 토큰이 **무엇을 전달하는가** (내용)

Q와 모든 K를 내적해 관련도를 구하고, softmax로 비율을 만든 뒤, 그 비율로 V를 가중합한다.

**V가 K와 따로 필요한 이유**는 "어떻게 찾힐지"와 "무엇을 줄지"의 목적이 다르기 때문이다. 하나로 합치면 한 벡터가 두 역할을 타협해 수행해야 하지만, 분리하면 **독립적으로 최적화**할 수 있다.

**3. 한계**

- **계산 복잡도가 O(n²)** 이다. 모든 토큰 쌍을 계산하므로 토큰이 2배면 계산은 4배가 된다. **컨텍스트 윈도우가 무한정 길어지지 못하는 근본 이유**다.
- 모든 토큰을 동시에 보기 때문에 **순서를 알 수 없다.** 이는 **위치 인코딩**으로 순서 정보를 주입해 해결한다.

## 검토 결과

### 확인된 부분

- **동음이의어로 셀프 어텐션의 목적을 정확히 설명함.** 임베딩(정적) → 문맥 반영이라는 흐름을 잡음. → [[2026-08-03-ai-data-embeddings]]
- 실습 Q2(순서를 모르는 이유)를 원인과 해법 모두 정확히 답함.
- `√d_k` 스케일링의 이유(분산 증가 → softmax 극단화 → 기울기 소실)를 정확히 서술함.

### 보강 포인트

- ⚠️ **가장 중요한 교정: Q는 "사용자가 입력한 질문"이 아니다.**
  - 초기 답변: *"Q는 Query이고 **LLM에 입력하는 질문이나 문장**을 의미"*
  - 실제로는 **문장 안의 모든 토큰이 Q, K, V를 전부 가진다.**

  ```text
  "배가 고프다"
    배     → Q_배,    K_배,    V_배
    가     → Q_가,    K_가,    V_가
    고프다 → Q_고프다, K_고프다, V_고프다
  ```

  - 사용자 질문이 Q이고 문서가 K/V인 것이 아니라, **같은 시퀀스의 같은 토큰들**에서 전부 나온다. 그래서 이름이 **"셀프(self)" 어텐션**이다.
  - 검색 비유는 **한 번의 매칭 과정**을 설명하는 것이지, Q가 외부 입력이라는 뜻이 아니다.

  **`배` 토큰의 시점에서 보면**
  ```text
  Q_배 = "나는 내 뜻을 정하려면 무엇을 봐야 하지?"
          ↓ 문장 안 모든 K와 내적
  K_고프다 와 잘 맞음 → 관련도 0.7
          ↓
  V_고프다 를 0.7만큼 가져와 내 벡터에 반영
  ```
  동시에 `고프다`도 자기 Q로 남들을 보고 있다. **모든 토큰이 동시에 이 과정을 수행한다.**

- **이동하는 것은 Q가 아니라 토큰의 표현(벡터)이다.** Q는 그 이동을 위해 만든 세 도구 중 하나.
- **"V가 왜 따로 필요한가"가 초기 답변에서 누락 → 추가.**
- **한계에 O(n²)이 누락 → 추가.** 순서 문제는 위치 인코딩으로 **해결되는** 문제지만, O(n²)은 **여전히 미해결 근본 제약**이다.

  | 한계 | 해결됐나 |
  |---|---|
  | 순서를 모름 | ✅ 위치 인코딩으로 해결 |
  | **O(n²) 복잡도** | ⚠️ **여전히 근본 제약** |

### 심화: V가 따로 필요한 이유

```text
K = "나를 어떻게 찾을 것인가"    ← 검색되기 위한 표지
V = "찾았을 때 무엇을 줄 것인가"  ← 실제 전달할 내용
```

**이 둘의 최적 형태가 다르다.**

| | 제목 (K) | 본문 (V) |
|---|---|---|
| 목적 | **찾히기 좋게** | **정보를 담기** |
| 형태 | 짧고 핵심 키워드 | 길고 상세 |
| 최적화 방향 | 검색어와 매칭 | 내용 전달 |

**K를 V로 겸하면** 하나의 벡터가 *"`고프다`라는 Query에 잘 걸려야 하고, 동시에 음식이라는 의미도 잘 전달해야 한다"* 는 **타협을 강제받는다.** 검색에 최적화하면 정보가 빈약해지고, 정보에 최적화하면 검색이 부정확해진다.

`W_K`와 `W_V`를 분리하면 모델이 **"어떻게 찾힐지"와 "무엇을 줄지"를 독립적으로 학습**할 수 있다. Q와 K가 분리된 것도 같은 이유 — "내가 찾는 것"과 "내가 제공하는 것"은 다르다.

### 계산 4단계

```text
Attention(Q, K, V) = softmax( Q·Kᵀ / √d_k ) · V
```

| 단계 | 연산 | 하는 일 |
|---|---|---|
| ① 점수 | `Q · Kᵀ` | 내 Query와 모든 Key를 내적 → **관련도 점수** |
| ② 스케일 | `÷ √d_k` | 값이 너무 커지는 것 방지 |
| ③ 정규화 | `softmax` | 점수 → **합이 1인 주목 비율** |
| ④ 가중합 | `× V` | 그 비율로 Value를 섞음 → **새 벡터** |

```text
"배가 고프다" 에서 배의 시선:
  배 → 고프다  관련도 0.7  ← 여기에 주목
  배 → 가      관련도 0.2
  배 → 배      관련도 0.1
        ↓
  새 배 벡터 = 0.7×V(고프다) + 0.2×V(가) + 0.1×V(배)  → 음식 쪽으로 이동
```

### 곁가지 개념

- **멀티헤드 어텐션**: 어텐션을 여러 벌 병렬 수행. 하나의 어텐션은 **한 종류의 관계**만 잡으므로, 여러 헤드가 문법·지시·의미 관계를 나눠 맡는다.
- **인과 마스킹(Causal Masking)**: GPT 같은 디코더는 다음 토큰을 예측해야 하므로 **미래를 보면 안 된다.** 뒤쪽 토큰 점수를 `-∞`로 만들어 softmax 후 0이 되게 한다. → [[2026-07-22-ai-data-what-is-an-llm]]의 자기회귀 생성
- **RNN과의 대비**: RNN은 토큰을 **하나씩 순서대로** 처리해 순서가 구조에 내장돼 있었다. Transformer는 **병렬 처리를 얻는 대가로 순서를 잃었고**, 위치 인코딩으로 보충한다. 병렬 처리가 곧 학습 속도라 **좋은 거래**였다.

### 이전 학습과의 연결

- 파이프라인 위치: `텍스트 → 토큰 → 임베딩 → **셀프 어텐션** → 다음 토큰 예측` → [[2026-07-29-ai-data-tokenization]], [[2026-08-03-ai-data-embeddings]]
- **문맥 임베딩을 만드는 실제 장치**가 셀프 어텐션이다. 정적 임베딩이 문맥에 따라 달라지는 이유.
- **O(n²)이 컨텍스트 한계의 뿌리.** 한국어가 토큰을 더 먹어 컨텍스트가 빨리 차는 문제도 결국 여기로 이어진다. → [[2026-07-29-ai-data-tokenization]]
- 토큰이 파편화돼도 모델이 의미를 조립할 수 있는 이유가 바로 어텐션이다.
