## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 1. 언제 멈추나 — 기준 레포의 답

기준 레포의 답은 한 줄이다.

> **검증 오차가 최소일 때 멈춘다.**

```text
손실
 │ ╲
 │  ╲  검증 손실
 │   ╲        ╭──── 여기서부터 과적합
 │    ╲___  __╯
 │        ╲╱  ← 최소 지점 = 멈출 곳
 │ ╲
 │  ╲___ 훈련 손실 (계속 내려감)
 │      ‾‾‾‾‾‾‾‾‾‾‾‾‾‾
 └─────────────────────────▶ 에폭
```

훈련 손실은 계속 내려가지만, 검증 손실은 어느 순간부터 다시 오른다. 그 지점부터 모델이 **데이터를 외우기 시작**한 것이다 → [[2026-08-05-ai-data-bias-variance]]

### 그런데 "최소"는 실시간으로 알 수 없다

**검증 손실은 매끄럽게 움직이지 않는다.** 미니배치·드롭아웃 같은 무작위성 때문에 들쭉날쭉하다.

```text
에폭:     10    11    12    13    14    15
검증손실: 0.42  0.40  0.41  0.39  0.40  0.43
                ↑           ↑
           여기가 최소인가?  아니었다, 여기가 더 낮다
```

**어느 에폭이 최소였는지는 지나고 나서야 안다.** 한 번 올랐다고 바로 멈추면 조금 뒤의 더 좋은 지점을 놓친다.

#### 해법 — 인내(Patience)

**"`N`번 연속으로 개선되지 않으면 멈춘다."**

| 설정 | 뜻 |
|---|---|
| **patience** | 개선 없이 몇 번까지 기다릴지 (예: 10 에폭) |
| **min_delta** | 이만큼은 줄어야 "개선"으로 친다 (잡음 수준의 변화 무시) |

[[2026-08-21-ai-data-gradient-boosting]]에서 본 "검증 오차가 50번 연속 개선되지 않으면 멈춘다"가 이것이다.

#### 그러면 새 문제가 생긴다

patience가 10이면, **멈춘 시점은 최소 지점보다 10 에폭 뒤**다. 그 10 에폭 동안 모델은 이미 과적합 방향으로 움직였다.

```text
에폭 13 : 최소 (검증 0.39)          ← 우리가 원하는 모델
에폭 14~23 : 개선 없음
에폭 23 : 멈춤 (검증 0.45)          ← 지금 메모리에 있는 모델
```

**지금 가진 가중치는 최선이 아니다.** 에폭 13의 가중치로 **되돌려야** 한다. 그러려면 **에폭 13의 가중치를 어딘가 저장해 뒀어야** 한다.

> 🔑 **이것이 조기 종료에 체크포인팅이 반드시 필요한 이유다.** 조기 종료는 "언제 멈출지"를 정하고, 체크포인팅은 "최선의 순간을 되돌릴 수 있게" 해 준다.

### 무엇을 기준으로 볼 것인가 — 손실 vs 지표

| 기준 | 장점 | 주의 |
|---|---|---|
| **검증 손실** | 매끄럽고 학습 목표와 일치 | 실제 관심 지표와 다를 수 있다 |
| **검증 지표**(정확도·F1·AUC 등) | **실제로 신경 쓰는 값** | 들쭉날쭉하다 |

**손실은 오르는데 정확도는 계속 오르는 경우**가 있다. 모델이 정답은 더 많이 맞히지만, 틀린 것에 대해서는 **점점 더 확신을 갖고 틀리기(과신)** 때문이다. 교차 엔트로피는 확신하고 틀리면 벌점이 크다. 이럴 때는 **실제 지표 기준**으로 멈추는 게 맞다 → [[2026-08-04-ai-data-classification-metrics]]

## 기준 답변

### 2. 모델 체크포인팅이란

기준 레포의 정의:

> **오래 걸리는 학습 도중에, 모델이 학습한 가중치를 저장해 두는 것.** 그래서 특정 시점부터 학습을 **다시 이어갈 수** 있게 한다.

#### 왜 필요한가 — 네 가지

| 목적 | 설명 |
|---|---|
| **① 장애 복구** | 수일짜리 학습 중 GPU 장애·서버 재시작·**선점형(spot) 인스턴스 회수**가 생기면 처음부터 다시 해야 한다. 체크포인트가 있으면 마지막 저장 지점부터 이어간다 |
| **② 최고 모델 보존** | 조기 종료와 짝. **검증 성능이 가장 좋았던 순간**을 따로 저장해 두고 마지막에 되돌린다 |
| **③ 시점 비교·분석** | 여러 시점의 모델을 비교하거나, 학습 곡선이 어디서 꺾였는지 확인한다 |
| **④ 재현성** | 같은 지점에서 설정만 바꿔 다시 돌려 볼 수 있다 |

**비용으로 보면**: 8대의 GPU로 7일 걸리는 학습이 6일째에 멈췄다면, 체크포인트가 없을 때 **48 GPU·일**을 날린다. 하루마다 저장했다면 잃는 건 **최대 하루치**다.

#### 무엇을 저장하나 — 가중치만으로는 부족하다

**이어서 학습하려면 "학습의 상태" 전체**가 필요하다.

| 저장할 것 | 없으면 무슨 일이 생기나 |
|---|---|
| **모델 가중치** | 당연히 필요 |
| **옵티마이저 상태** (Adam의 `m`, `v`) | 재개 직후 **모멘트가 0에서 다시 시작** → 초반처럼 불안정해진다 |
| **학습률 스케줄러 상태** | warmup을 **다시 처음부터** 하거나, 코사인 감소의 **엉뚱한 지점**에서 재개한다 |
| **현재 에폭·스텝** | 어디까지 했는지 모른다 |
| **난수 상태·데이터 순서** | 같은 데이터를 두 번 보거나 일부를 건너뛴다. 재현이 깨진다 |

> 💡 [[2026-09-22-ai-data-adam-vs-sgd]]와 바로 이어진다. Adam은 파라미터마다 `m`(방향)과 `v`(보폭)를 들고 있다. 이걸 저장하지 않으면 재개 순간 **모든 파라미터가 "처음 보는 기울기"로 돌아가** 보폭 계산이 흔들린다. **가중치만 저장한 체크포인트는 "이어서 학습"이 아니라 "가중치로 초기화한 새 학습"** 이다.

#### 저장 비용 — Adam이면 약 3배

```text
가중치 1벌  +  Adam의 m 1벌  +  Adam의 v 1벌  =  모델 크기의 약 3배

7B 모델, FP32(4 bytes) 기준
  가중치       : 약 28 GB
  m + v        : 약 56 GB
  체크포인트 1개 : 약 84 GB
```

그래서 **전부 무한정 쌓아 두지 않는다.**

| 전략 | 내용 |
|---|---|
| **최근 N개만 유지** | 장애 복구용. 오래된 것은 지운다 |
| **최고 성능 1개 유지** | 조기 종료용. 검증 성능이 갱신될 때만 덮어쓴다 |
| **저장 주기 조절** | 에폭마다 또는 `N` 스텝마다. 너무 자주 저장하면 저장 자체가 학습을 느리게 한다 |
| **배포용은 가중치만** | 추론에는 옵티마이저 상태가 필요 없다 → 크기가 1/3로 준다 |

### ⚠️ 이름이 비슷한 다른 개념 — 그래디언트 체크포인팅

[[2026-09-04-ai-data-backpropagation]]에서 본 **그래디언트 체크포인팅(gradient checkpointing)** 과 **완전히 다른 것**이다.

| | **모델 체크포인팅** | **그래디언트 체크포인팅** |
|---|---|---|
| 무엇을 저장하나 | 학습 상태 전체를 **디스크에** | 순전파 중간 활성값 **일부만 메모리에** |
| 목적 | **복구·보존·재현** | **학습 중 GPU 메모리 절약** |
| 대가 | 디스크 공간, 저장 시간 | **역전파 때 재계산**(연산 증가) |
| 언제 | 학습 **사이사이** | 한 스텝의 **역전파 안에서** |

**이름만 같고 푸는 문제가 다르다.** 면접에서 섞어 말하면 곧바로 드러나는 지점이다.

### 모델 종류별로 어떻게 다른가 — LLM만의 이야기가 아니다

**조기 종료는 반복해서 학습하는 모델이면 어디든** 쓴다. 기준은 신경망 크기가 아니라 **"조금씩 반복하며 나아가는가"** 다.

| 모델 | 조기 종료 | 비고 |
|---|---|---|
| **신경망** (작은 MLP부터 LLM까지) | ✅ | 에폭·스텝 단위 |
| **그래디언트 부스팅** (XGBoost·LightGBM·CatBoost) | ✅ **실무에서 가장 흔함** | `early_stopping_rounds` — 트리 개수 단위 |
| **SGD로 학습하는 선형 모델** | ✅ | scikit-learn `SGDClassifier(early_stopping=True)` |
| 선형 회귀 (정규방정식) | ❌ | 한 번에 답을 계산해 "중간"이 없다 |
| KNN | ❌ | 학습 과정 자체가 없다 |
| 결정 트리 | ❌ | 대신 깊이 제한·가지치기 |
| 랜덤 포레스트 | ❌ (필요 없음) | 트리를 늘려도 과적합이 늘지 않는다 |

**체크포인팅은 모델이 과거를 "덮어쓰느냐, 쌓아 가느냐"로 필요성이 갈린다.**

```text
부스팅 : 트리를 계속 "추가"한다
         트리 1, 2, … 130(최고), 131, … 180(멈춤)
         → 131~180번 트리를 쓰지 않으면 최고 시점으로 돌아간다
         → 과거 상태가 그대로 남아 있다

신경망 : 같은 가중치를 계속 "덮어쓴다"
         에폭 13(최고) → 에폭 14에서 덮어씀 → … → 에폭 23
         → 에폭 13의 가중치는 이미 사라졌다
         → 미리 따로 저장해 뒀어야 한다
```

그래서 부스팅 라이브러리는 **최고 반복 횟수(`best_iteration`)를 기억해 두고 예측 때 그 지점까지의 트리만 쓴다**(CatBoost의 `use_best_model`도 같은 기능). 별도 체크포인트가 필요 없다.

| | 조기 종료 | 체크포인팅 |
|---|---|---|
| **신경망 (LLM 포함)** | ✅ | ✅ **필수** — 가중치를 덮어쓰므로 |
| **부스팅** | ✅ **표준** | 사실상 불필요 — 트리를 쌓아 가므로 |
| **한 번에 끝나는 모델** | ❌ | ❌ — 다시 학습하면 됨 |

전통 ML처럼 학습이 몇 초~몇 분이면, 끝난 모델을 `joblib`·`pickle`로 저장하는 **모델 저장(persistence)** 만 하면 된다. **옵티마이저 상태까지 저장하는 문제는 경사하강법으로 오래 학습하는 신경망에만** 해당한다.

### 한 문장 요약

> **학습은 검증 성능이 가장 좋을 때 멈추지만, 그 최소는 지나고 나서야 알 수 있으므로 patience를 두고 기다린다. 그 사이 모델이 이미 나빠지므로 최고 시점의 상태를 저장해 두었다가 되돌려야 하는데, 이것이 체크포인팅이다. 이어서 학습하려면 가중치뿐 아니라 옵티마이저·스케줄러·스텝·난수 상태까지 저장해야 한다.**

## 내가 정리한 내용

### 1. 조기 종료에 체크포인팅이 필요한 이유

- 검증 손실은 매끄럽게 움직이지 않고 들쭉날쭉해 **patience**를 둔다.
- 근데 patience가 10이면 학습이 멈춘 시점은 **최적 지점보다 10 에폭 뒤**다.
- 따라서 **최고 시점의 가중치로** 되돌려야 하고, 되돌리기 위해서는 **체크포인팅**이 필요하다.

### 2. 가중치만 저장하고 재개하면

- 옵티마이저 상태를 저장하지 않으면 학습 재개 이후 **모멘트가 0에서 다시 시작**되므로 **초반 학습처럼 불안정**하다.

### 3. 모델 체크포인팅 vs 그래디언트 체크포인팅

- **모델 체크포인팅**은 학습 상태 전체를 **디스크에**, **복구·보존·재현**을 위해 저장한다.
- **그래디언트 체크포인팅**은 중간 활성값 일부를 **메모리에**, **GPU 메모리 절약**을 위해 저장한다.

## 검토 결과

### 확인된 부분

- **patience → 멈춘 시점이 최적보다 뒤 → 되돌리려면 저장이 필요**라는 인과 사슬을 순서대로 세웠다. 두 개념이 왜 짝인지를 정확히 설명했다.
- **옵티마이저 상태를 잃으면 모멘트가 0부터 다시 시작한다**는 점을 Adam 노트와 연결해 짚었다.
- **이름이 비슷한 두 체크포인팅**을 **무엇을·어디에·왜** 세 축으로 구분했다.
- 대화 중 **"LLM만이 아니라 ML에도 적용되나?"** 를 스스로 물어, 개념의 **적용 범위**를 확인했다. 그 답에서 **"덮어쓰기 vs 쌓아 가기"** 라는 구분이 나왔다.

### 보강 포인트

#### ① 되돌리는 대상은 에폭이 아니라 가중치

| | 내용 |
|---|---|
| **전** | **에폭을** 되돌려야 하고 |
| **후** | **최고 시점의 가중치로** 되돌려야 하고 |

이 목적이라면 매 에폭 전부 저장할 필요가 없다. **검증 성능이 갱신될 때만 덮어쓰는(save best only)** 방식이면 최고 모델 하나만 남는다.

#### ② "불안정"의 실체, 그리고 스케줄러도 함께 흔들린다

모멘트가 0에서 다시 시작하면 Adam의 **첫 스텝**은 이렇게 된다.

```text
m̂ = g,  v̂ = g²   (편향 보정 후)
갱신량 = η · g / √(g²) = η · g / |g| = η · (기울기의 부호)
```

**모든 파라미터가 기울기 크기와 상관없이 똑같이 `±η`만큼 움직인다.** 쌓아 둔 "이 파라미터는 조심히, 저 파라미터는 과감히"라는 정보가 사라지고 모두가 같은 보폭으로 튄다.

그리고 **학습률 스케줄러 상태**도 잃으면 warmup이 처음부터 다시 시작되거나, 이미 작게 줄어 있던 학습률이 **큰 값으로 튀어 오를 수** 있다. **옵티마이저와 스케줄러가 둘 다 흔들린다.**

#### ③ 두 체크포인팅의 대가와 시점

| | 모델 체크포인팅 | 그래디언트 체크포인팅 |
|---|---|---|
| 무엇을·어디에 | 학습 상태 전체 → **디스크** | 중간 활성값 일부 → **메모리** |
| 목적 | 복구·보존·재현 | GPU 메모리 절약 |
| **대가** | 디스크 공간, 저장 시간 | 역전파 때 **재계산**(연산 증가) |
| **언제** | 학습 **사이사이** | 한 스텝의 **역전파 안에서** |

그래디언트 체크포인팅은 KV 캐시·MoE·Flash Attention에서 계속 본 **연산↔메모리 거래**의 하나이고, 모델 체크포인팅은 그런 거래와 무관한 **학습 운영의 안전장치**다.

### 심화: 덮어쓰기 vs 쌓아 가기

체크포인팅이 필요한지는 **모델이 학습하면서 과거를 어떻게 다루는가**로 갈린다.

- **신경망**은 같은 가중치를 매 스텝 **덮어쓴다** → 과거로 돌아가려면 미리 저장해야 한다.
- **부스팅**은 트리를 **쌓아 간다** → 뒤쪽 트리만 안 쓰면 과거로 돌아간다. 그래서 `best_iteration`만 기억하면 된다.

같은 "조기 종료"라도 **구조가 다르면 필요한 장치가 달라진다.** 개념을 외우기보다 **구조에서 필요성을 유도**하는 사례다.

### 심화: 손실은 오르는데 정확도는 오를 때

모델이 정답은 더 많이 맞히지만, 틀린 것에는 **점점 더 확신하며 틀리는(과신)** 경우다. 교차 엔트로피는 확신하고 틀리면 벌점이 크므로 손실이 오른다. 이럴 때는 **실제로 신경 쓰는 지표**(정확도·F1·AUC) 기준으로 멈추는 것이 맞다 → [[2026-08-04-ai-data-classification-metrics]]

### 이전 학습과의 연결

- [[2026-08-05-ai-data-bias-variance]] — 조기 종료는 **분산(과적합)을 줄이는 정규화 수단**이다. 검증 손실이 다시 오르는 지점이 과적합의 시작이다.
- [[2026-08-21-ai-data-gradient-boosting]] — 부스팅의 조기 종료(patience 50)가 오늘의 patience와 같다. 그리고 부스팅은 **트리를 쌓아 가서 체크포인트 없이도 최고 시점으로 돌아간다.**
- [[2026-09-22-ai-data-adam-vs-sgd]] — Adam의 `m`, `v`를 저장하지 않으면 재개 직후 **모든 파라미터가 `±η`로 튄다.** 스케줄러 상태를 잃으면 warmup이 다시 시작된다.
- [[2026-09-04-ai-data-backpropagation]] — **그래디언트 체크포인팅**은 이름만 비슷한 다른 개념이다(메모리 절약용 재계산).
- [[2026-07-30-ai-data-validation]] — 멈출 시점을 판단하는 **검증 세트**가 여기서 쓰인다. 테스트 세트로 멈추면 테스트가 오염된다.
- [[2026-08-04-ai-data-classification-metrics]] — 손실과 지표가 엇갈릴 때 **지표 기준**으로 멈춘다.
