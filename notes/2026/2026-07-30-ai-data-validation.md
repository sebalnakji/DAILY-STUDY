## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

- **과적합(Overfitting)**: 학습 데이터에는 매우 잘 맞지만 테스트 데이터로 **일반화되지 않는** 상태. 학습 데이터에 과도하게 맞춰졌기 때문. → 첫날 배운 *"목표는 학습 데이터가 아니라 처음 보는 데이터를 잘 맞히는 것"* 의 실패 사례. [[2026-07-20-ai-data-supervised-learning]]

### 3분할 (train / validation / test)

| 세트 | 용도 | 모델이 보나 |
|---|---|---|
| **train(학습)** | 모델을 학습(fit)시킨다 | ✅ 직접 학습 |
| **validation(검증)** | **하이퍼파라미터 튜닝**과 모델 선택 | ⚠️ 간접적으로 반영됨 |
| **test(시험)** | 최종 성능 측정 | ❌ **한 번도 안 봄** |

- validation이 따로 필요한 이유: 하이퍼파라미터를 고르는 데 쓴 데이터로 최종 평가를 하면, **그 데이터에 맞춰 고른 것**이므로 편향된(낙관적인) 점수가 나온다.
- **평가는 절대 학습에 쓴 데이터로 하지 않는다.** 그러면 성능이 대표성을 갖지 못한다.

### 교차검증(Cross-Validation)

- 학습 데이터를 train/validation으로 나누는 과정을 **여러 번 반복**하며, 매번 다른 부분을 validation으로 쓴다.
- 목적: **하나의 validation 세트만 골랐을 때 생기는 편향(bias)을 줄인다.**

### K-Fold 교차검증

- 데이터를 `K`개로 분할한다.
- 1번째 조각을 validation, 나머지 `K-1`개를 train으로 학습 → 2번째 조각을 validation, 나머지를 train → ... 반복.
- **각 조각이 정확히 한 번씩 validation 역할**을 한다. 결과 `K`개를 평균해 성능을 추정.
- ⚠️ **시계열(time series) 데이터에는 사용하면 안 된다.** (미래 데이터로 과거를 예측하는 누수가 발생)

### K를 어떻게 고르나

두 가지를 함께 고려한다.

1. **모델 개수**: 2~3개는 너무 적다. 최소 4개는 되어야 지표 판단의 편향이 줄어든다.
2. **validation 세트 크기**: 전체의 최소 20~25%는 되어야 한다. 즉 train:validation이 최소 **3:1**.

- 원문 저자 기준: 작은 데이터셋엔 `K=4`, 큰 데이터셋엔 `K=5`.

### 조합해서 쓰기

**test(holdout) 세트를 먼저 떼어두고, 남은 데이터로 교차검증**한 뒤, 최종 품질은 test로 측정한다. 실무에서 가장 견고한 방식.

## 기준 답변

기준 레포의 답변을 바탕으로 핵심만 재구성한다.

**과적합**은 모델이 학습 세트에서는 매우 잘 동작하지만 테스트 세트로 일반화하지 못하는 것이다. 학습 세트에 과도하게 맞춰졌기 때문이다.

**모델 검증 방법**으로 가장 흔한 접근은 데이터를 train, validation, test로 나누는 것이다. 모델은 train으로 학습하고, 하이퍼파라미터(예: early stopping)는 validation을 보고 선택하며, 최종 측정은 test에서 한다. 또 다른 접근은 **교차검증**으로, 데이터셋을 `K`개 폴드로 나눠 매번 학습 폴드로 학습하고 검증 폴드에서 성능을 측정한다. 두 방식을 결합할 수도 있다 — test/holdout을 만들고 나머지로 교차검증한 뒤, 최종 품질은 test에서 측정한다.

**왜 셋으로 나누는가**: train은 모델을 학습시키는 데 쓴다. validation은 하이퍼파라미터를 조정하는 동안 **편향 없는 평가**를 제공해 일반화 성능을 높인다. 마지막으로 모델이 한 번도 본 적 없는 test로 최종 평가를 해야 편향 없는 평가가 가능하다. **평가를 학습에 쓴 데이터로 하면 성능이 대표성을 갖지 못한다.**

**K-Fold 교차검증**은 데이터를 `K`개로 나눠 각 조각이 한 번씩 validation이 되도록 반복하는 방법이다. 시계열 데이터에는 쓰지 않아야 한다.

## 내가 정리한 내용

**1. 과적합(Overfitting)이란?**

특정 데이터에 과도하게 맞춰져, **학습 데이터에는 매우 잘 맞지만 처음 보는 데이터에서는 성능이 떨어지는** 상태. 즉 일반화에 실패한 것이다.

**2. 왜 train / validation / test 셋으로 나누는가**

- **train**: 모델을 학습하기 위한 데이터
- **validation**: 모델을 튜닝(하이퍼파라미터 선택)하기 위한 데이터
- **test**: 모델의 성능을 최종 확인하기 위한 데이터

validation과 test를 분리하는 이유는, **validation 점수를 보고 설정을 고르는 순간 validation이 선택의 기준이 되어 편향되기** 때문이다. 그 데이터로 최종 평가를 하면 낙관적인 점수가 나온다. 따라서 **한 번도 쓰지 않은 test**가 따로 필요하며, 모델을 완성한 후 **딱 한 번만** 사용해야 한다.

**3. K-Fold 교차검증(Cross-Validation)이란?**

`K`에 따라 데이터를 분할하고, 분할된 데이터 중 하나를 **돌아가면서 검증 데이터로 사용**한다. 그렇게 나온 결과의 **평균**을 모델 성능으로 삼는다.

이렇게 하는 이유는, 검증 데이터를 한 번만 랜덤으로 선정하면 그 데이터가 **쉽거나 어려워서 생기는 편향**이 일어날 수 있기 때문이다.

## 검토 결과

### 확인된 부분

- **K-Fold의 메커니즘과 이유를 모두 정확히 서술함.** "돌아가면서 검증", "결과의 평균", 그리고 이유로 **"한 번만 뽑으면 쉽거나 어려운 편향"** 까지 짚음. 이 항목은 보강할 것이 없다.
- 세 세트의 역할 구분이 정확하고, **"test는 완성 후 딱 한 번만"** 이라는 실무 원칙을 명시함.
- 실습 Q2(주식 예측 95%)에서 시계열에 K-Fold를 쓰면 안 되는 이유를 정확히 진단.
- Q1에서 처방(validation 분리 → 최종에만 test, K-Fold 활용)을 정확히 제시.

### 보강 포인트

- **과적합 정의는 "대비 구조"로 말할 것.** 특징은 "성능이 나쁘다"가 아니라 **"학습은 너무 좋고 검증은 나쁘다"** 는 비대칭이다. 그래서 실무에서는 **train과 validation 점수의 격차**로 과적합을 진단한다.
- **train/validation/test 분리는 "무엇"보다 "왜"가 채점 포인트.** 초기 답변은 역할만 서술 → **"편향"** 이라는 단어를 넣어야 완성된다. 3번에서 쓴 편향 논리와 같다.
  - 원칙: **선택에 쓴 데이터는 평가 자격을 잃는다.**
- **Q1의 진짜 문제: 과적합하는 주체가 모델이 아니라 "나"다.** (초기 답변은 일반적 과적합으로 서술)
  ```text
  모델은 test로 학습하지 않았다.          ← 모델은 결백
  그런데 내가 test 점수를 보고 설정을 골랐다. ← 내가 test에 맞췄다
  ```
  - 정확한 명칭: **test 세트에 대한 과적합(overfitting to the test set)**.
  - 결과: **test 점수를 신뢰할 수 없게 된다.** `depth=3,5,10`을 test에서 비교해 최고를 골랐다면 그 점수는 "test에서 가장 운 좋았던 설정의 점수"이지 실전 성능이 아니다.
  - 위험한 이유: **코드도 안 틀리고 에러도 없다. 숫자만 거짓말을 한다.** 그래서 조용히 지나가는 실무 사고의 단골.
- **Q2 심화 — 정확한 용어는 데이터 누수(Data Leakage).**
  ```text
  학습: 3월, 5월   ← 5월(미래)을 보고
  검증: 4월        ← 4월(과거)을 예측 = 실전에 없는 반칙
  ```
  실전에서는 4월 예측 시 5월을 절대 모른다. 95%는 실력이 아니라 **컨닝 점수**다.
- **해법: 시계열 교차검증(Walk-Forward Validation).**
  ```text
  1회차: [학습] [검증]
  2회차: [학습  학습] [검증]
  3회차: [학습  학습  학습] [검증]
          → 항상 과거로 학습, 그 다음 구간을 검증
  ```
  `sklearn`의 `TimeSeriesSplit`이 이 방식이다. **시계열은 섞으면 안 되고 앞에서 뒤로만 간다.**

### K를 고르는 기준

두 요구가 **서로 반대 방향**이라 타협이 필요하다.

| 고려사항 | 요구 | K는 |
|---|---|---|
| 모델 개수 | 최소 4개 이상 (2~3개는 편향) | 커야 함 |
| 검증 세트 크기 | 전체의 20~25% 이상 (train:validation ≥ 3:1) | 작아야 함 |

원문 저자 기준: 작은 데이터셋 `K=4`, 큰 데이터셋 `K=5`.

### 실무 최강 조합

```text
전체 데이터 ──┬── test (holdout)  ← 봉인. 맨 마지막에 한 번만
              └── 나머지 ── K-Fold 교차검증으로 튜닝
```

test를 먼저 떼어 봉인하고, 남은 데이터로 교차검증해 모델을 고른 뒤, **마지막에 딱 한 번** test로 평가한다.
