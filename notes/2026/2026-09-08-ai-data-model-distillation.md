## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 문제 설정 — 좋은 모델은 너무 크다

| | 큰 모델 | 작은 모델 |
|---|---|---|
| 성능 | 높다 | 낮다 |
| 추론 비용 | 비싸다 | 싸다 |
| 지연시간 | 느리다 | 빠르다 |
| 배포 | 서버 필요 | **폰·엣지 가능** |

**성능은 큰 모델을, 비용은 작은 모델을 원한다.** 증류는 이 둘을 절충하려는 시도다.

**정의**: **큰 교사(teacher) 모델이 학습한 지식을 작은 학생(student) 모델로 옮기는 기법.**

```text
   교사 모델 (크고 느리고 똑똑함)
        │  지식 전달
        ▼
   학생 모델 (작고 빠르고, 혼자 학습했을 때보다 똑똑함)
```

핵심 주장은 이것이다 — **같은 데이터로 학생을 처음부터 학습시키는 것보다, 교사를 흉내 내게 하는 편이 더 낫다.**

### 왜 그런가 — 정답 라벨은 정보가 빈약하다

이미지 분류에서 정답 라벨은 **원-핫(one-hot)** 이다.

```text
정답 라벨(하드 타깃)          교사의 출력 분포(소프트 타깃)
고양이  1.0                    고양이  0.90
개      0.0                    개      0.08
호랑이  0.0                    호랑이  0.019
자동차  0.0                    자동차  0.001
```

**두 벡터가 담은 정보량이 완전히 다르다.**

정답 라벨은 "고양이가 맞고 나머지는 다 틀렸다"만 말한다. **틀린 것들끼리는 전부 동등하게 틀렸다**고 취급한다.

교사의 분포는 다르다. **"이 이미지는 고양이지만, 굳이 틀린다면 개 쪽이지 자동차는 절대 아니다"** 를 말해 준다. 즉 **클래스들 사이의 유사 관계**를 담고 있다.

> 💡 Hinton은 이 정보를 **암흑 지식(dark knowledge)** 이라고 불렀다. 정답에 가려 보이지 않지만, 교사가 데이터에서 배운 **구조**가 바로 여기 들어 있다.

> 🏫 **비유**: 시험 답안지에 정답만 적힌 것과, **오답 선지마다 "이건 아깝게 틀렸고 저건 완전히 엉뚱하다"는 선생님의 코멘트가 달린 것**의 차이다. 후자가 배우기 훨씬 좋다.

### 온도(Temperature)가 여기서 다시 등장한다

문제가 하나 있다. 잘 학습된 교사는 확신이 강해서 분포가 **뾰족하다.**

```text
고양이 0.99, 개 0.008, 호랑이 0.0019, 자동차 0.0001
                └────────────────────────────┘
              여기 담긴 유사 관계가 너무 작아 학습 신호가 안 된다
```

그래서 **소프트맥스에 온도 `T`를 넣어 분포를 부드럽게 만든다.**

```text
softmax(zᵢ / T)

T = 1  → 원래 분포 (뾰족)
T = 4  → 평평해져서 작은 확률들의 상대 크기가 드러남
```

| | `T = 1` | `T = 4` |
|---|---:|---:|
| 고양이 | 0.99 | 0.55 |
| 개 | 0.008 | 0.22 |
| 호랑이 | 0.0019 | 0.15 |
| 자동차 | 0.0001 | 0.08 |

> 🔗 **[[2026-08-28-ai-data-temperature-sampling]]에서 배운 그 온도와 같은 장치인데 목적이 정반대다.**
>
> | | 온도의 용도 |
> |---|---|
> | 텍스트 생성 | 출력의 **다양성**을 조절 (`T↑` → 창의적, `T↓` → 결정적) |
> | 지식 증류 | 교사에게서 **정보를 더 뽑아내기** (`T↑` → 숨은 유사 관계가 드러남) |
>
> 같은 수식이 **쓰이는 자리에 따라 전혀 다른 문제를 푼다.**

**학습할 때만 `T`를 크게 쓰고, 배포된 학생 모델은 `T = 1`로 추론한다.**

### 손실 함수 — 두 스승을 함께 따른다

```text
L = α · CE(학생, 정답 라벨)  +  (1 − α) · T² · KL(학생 ‖ 교사)
        └──────────────┘           └──────────────────┘
          하드 손실                     소프트 손실
        "정답을 맞혀라"              "교사를 흉내 내라"
```

| 항 | 역할 |
|---|---|
| **하드 손실** | 정답 라벨과의 교차 엔트로피(Cross-Entropy). 교사가 틀렸을 때 학생이 함께 틀리는 걸 막는다 |
| **소프트 손실** | 교사 분포와의 KL 발산(Kullback-Leibler Divergence). 암흑 지식을 옮긴다 |
| **α** | 둘의 균형을 잡는 하이퍼파라미터 → [[2026-08-31-ai-data-hyperparameter-tuning]] |
| **T²** | 온도를 올리면 기울기가 `1/T²`로 작아지므로, **곱해서 스케일을 되돌린다** |

이 손실이 [[2026-09-04-ai-data-backpropagation]]의 역전파를 타고 학생 모델의 가중치로 흐른다. **증류는 새로운 학습 알고리즘이 아니라, 손실 함수를 바꾼 것뿐이다.**

## 기준 답변

### LLM에서의 증류 — 세 가지 방식

| 방식 | 무엇을 맞추나 | 특징 |
|---|---|---|
| **로짓 증류**(logit distillation) | 교사의 **출력 확률 분포** | 고전적 방식. 교사의 로짓에 접근할 수 있어야 한다 |
| **특징 증류**(feature distillation) | 중간 층의 **은닉 표현**까지 | 더 촘촘한 신호. DistilBERT·TinyBERT |
| **데이터/시퀀스 증류** | 교사가 **생성한 텍스트** | 교사를 API로만 써도 된다. **오늘날 LLM에서 가장 흔함** |

**세 번째가 요즘 LLM 판의 주류다.** 큰 모델에게 질문–답변 쌍을 잔뜩 생성하게 하고, 그 데이터로 작은 모델을 **지도 파인튜닝(SFT, Supervised Fine-Tuning)** 한다. Alpaca·Vicuna 계열이 이 방식으로 만들어졌다.

```text
GPT-4급 모델 ──▶ "질문 5만 개에 답해 줘" ──▶ 합성 데이터셋
                                                  │
                                                  ▼
                                        작은 오픈 모델을 SFT
```

> 💡 이 방식은 **교사의 내부(로짓·은닉 상태)에 접근할 필요가 없다.** API로 텍스트만 받으면 된다. 그래서 **접근성이 좋고**, 동시에 뒤에서 볼 **법적 문제의 진원지**가 된다.

**대표 성과 — DistilBERT**

| 항목 | 결과 |
|---|---|
| 파라미터 | BERT 대비 **약 40% 감소** |
| 추론 속도 | **약 60% 향상** |
| 성능 | 언어 이해 능력의 **약 97% 유지** |

### 다른 모델 압축 기법과의 비교

| 기법 | 방식 | 성격 |
|---|---|---|
| **증류**(Distillation) | 작은 모델을 **새로 학습**시킨다 | 구조를 자유롭게 바꿀 수 있다. **재학습 필요** |
| **양자화**(Quantization) | 가중치 **정밀도를 낮춘다** (FP16 → INT8/INT4) | 구조 그대로. 학습 없이도 가능 → [[2026-09-02-ai-data-kv-cache]] |
| **가지치기**(Pruning) | 중요도 낮은 **가중치를 제거**한다 | 희소해져 실제 속도 이득을 보려면 하드웨어 지원이 필요 |

**셋은 배타적이지 않다.** 증류한 학생 모델을 다시 양자화하는 식으로 겹쳐 쓴다.

### 법적 고려사항

두 번째 질문이 묻는 부분이다. **데이터/시퀀스 증류가 흔해지면서 실무 쟁점이 됐다.**

| 쟁점 | 내용 |
|---|---|
| **이용약관(ToS) 위반** | 주요 상용 API는 **"출력물로 경쟁 모델을 학습시키지 말 것"** 을 명시한다. 증류가 정면으로 이 조항에 걸린다 |
| **출력물의 저작권 귀속** | AI 생성물의 저작권 상태가 관할권마다 불명확하다. "누구의 것인가"가 정리되지 않았다 |
| **라이선스 전파** | 오픈 가중치 모델도 라이선스가 **파생 모델에 조건을 물릴 수 있다**(예: Llama 커뮤니티 라이선스의 명명·사용 조건) |
| **편향·오류의 전이** | 교사의 편향·환각이 학생에게 **그대로 옮겨간다.** 책임 소재가 흐려진다 |
| **개인정보 유출** | 교사가 학습 데이터를 암기했다면, 증류 데이터를 통해 **학생에게 흘러들어갈 수 있다** |

> ⚠️ **기술적으로 가능한 것과 계약상 허용되는 것은 다르다.** 증류 자체는 오래된 정당한 기법이지만, **누구의 출력을 교사로 쓰느냐**에 따라 계약·저작권 문제가 발생한다. 면접에서 이 구분을 명확히 하면 좋다.

### 한 문장 요약

> **증류는 교사 모델의 "틀린 답들 사이의 상대적 유사도"까지 학생에게 물려주는 기법이다. 정답 라벨이 못 주는 그 정보를 온도로 끄집어내고, 하드 손실과 소프트 손실의 가중합으로 학습시킨다. 새로운 학습 알고리즘이 아니라 손실 함수를 바꾼 것이다.**

## 내가 정리한 내용

### 1. 증류가 푸는 문제와 정의

- **큰 교사(teacher) 모델이 학습한 지식을 작은 학생(student) 모델로 옮기는 기법.**
- **성능은 큰 모델에 가깝게, 비용은 작은 모델 수준으로** 만들려는 방법이다.

### 2. 왜 교사를 거치면 더 나은가

- 정답 라벨에는 정답 말고는 **나머지를 전부 동등하게 취급**한다. 하지만 교사의 출력 분포는 **클래스들 사이의 유사 관계**를 담고 있다.
- 그 유사 관계 정보는 **교사가 학습한 데이터 전체에 흩어져 있던 정보를, 한 예시의 출력으로 응축한 것**이다.

```text
"개와 고양이는 헷갈리고, 고양이와 자동차는 안 헷갈린다"
→ 이미지 한 장의 라벨에는 없다
→ 데이터셋 전체(수백만 장)에는 통계로 존재한다
→ 교사가 학습해 내부 표현에 압축했고
→ 이미지 한 장을 넣으면 그 압축된 지식이 출력 분포로 나온다
```

학생이 혼자 배우려면 그 통계를 **데이터 전체에서 스스로 다시 발굴**해야 한다. 교사를 쓰면 **예시 한 장마다 그 결론을 완성된 형태로 받는다.**

### 3. 온도의 역할

온도를 올리면 **기울기가 생겨, 학습 신호가 안 되던 정보를 학습 신호로 만들 수 있다.**

```text
T = 1 : 개 0.008 vs 자동차 0.0001 → 둘 다 0에 가까워 KL 손실에 거의 기여 안 함
                                    → 기울기가 사실상 0 → 배울 유인이 없다
T = 4 : 개 0.22  vs 자동차 0.08    → 차이가 손실에 실질적으로 기여
                                    → 기울기가 생긴다 → 실제로 학습된다
```

다만 온도에는 **양면**이 있다 — 개별 클래스 간 차이는 **키우지만**, 전체 기울기 크기는 **`1/T²`로 줄인다.** 그래서 손실 함수에서 **소프트 항에 `T²`를 곱해 스케일을 되돌린다.**

학습할 때만 `T`를 크게 쓰고, 배포된 학생 모델은 `T = 1`로 추론한다.

### 4. LLM에서 데이터 증류가 주류인 이유와 그 문제

- **교사의 내부에 접근하지 않고 API로 텍스트만 받으면 돼 접근성이 좋다.**
- 그런데 **정상적인 사용과 구분이 되지 않아** 기술로 막을 수가 없다. 그래서 제공자는 **법적 장벽(이용약관)** 을 세운다.
- **기법을 문제 삼는 게 아니라 데이터 출처를 문제 삼는 것**이다. 증류 자체는 2015년부터 있던 정당한 기술이다.

| 쟁점 | 내용 |
|---|---|
| **이용약관 위반** | 주요 상용 API가 "출력물로 경쟁 모델 학습 금지"를 명시 |
| **출력물의 저작권 귀속** | AI 생성물의 저작권 상태가 관할권마다 불명확 |
| **라이선스 전파** | 오픈 가중치 모델도 파생 모델에 조건을 물릴 수 있음 |
| **편향·오류 전이** | 교사의 편향·환각이 학생에게 옮겨가 책임 소재가 흐려짐 |
| **개인정보 유출** | 교사가 암기한 학습 데이터가 증류 데이터를 통해 흘러갈 수 있음 |

**탐지가 어렵다**는 점도 뒤따른다 — 어떤 모델이 남의 출력으로 학습됐는지 증명하기 어려워 **워터마킹**이나 **카나리(canary) 문자열** 논의가 나온다.

## 검토 결과

### 확인된 부분

- **"교사가 정보를 만든 게 아니라, 데이터 전체에 흩어져 있던 정보를 한 예시의 출력으로 응축했다"** 를 정확히 재구성했다. 표면 답("유사 관계를 담는다")에서 멈추지 않고 **정보의 출처**까지 갔다. 오늘의 핵심이다.
- **온도의 역할을 기울기 관점으로** 옮겼다 — "잘 보인다"가 아니라 **"기울기가 생긴다"** 로 말한 것이 정확하다. [[2026-09-04-ai-data-backpropagation]]에서 배운 "손실에 기여하지 않으면 기울기도 0"을 스스로 적용했다.
- **"기법을 문제 삼는 게 아니라 데이터 출처를 문제 삼는 것"** — 이 구분을 스스로 정리했다. 면접에서 그대로 쓸 수 있는 문장이다.
- 접근성과 법적 문제가 **같은 성질의 양면**이라는 구조를 정확히 잡았다.

### 보강 포인트

이번에는 사소한 세 가지뿐이다.

#### ① 문장이 반대로 읽힌다

| | 내용 |
|---|---|
| **전** | **성능은 크고 비용은 작은 모델**을 만들기 위한 방법 |
| **후** | **성능은 큰 모델에 가깝게, 비용은 작은 모델 수준으로** 만들려는 방법 |

"성능은 크고"는 성능의 크기인지 모델의 크기인지 모호하다. **무엇을 어느 쪽에서 가져오는지**를 명시해야 한다.

#### ② `T²` 보정이 빠졌다

온도의 **양면**을 함께 말해야 한다 — 개별 클래스 간 차이는 키우지만 전체 기울기 크기는 `1/T²`로 줄인다. 교정 후 내용은 위 `내가 정리한 내용` 3번에 반영.

#### ③ 법적 쟁점의 구체적 목록이 빠졌다

구조(접근성 ↔ 계약)는 정확했으나 **어떤 쟁점들인지**가 없었다. 교정 후 내용은 위 `내가 정리한 내용` 4번의 표에 반영.

### 심화: 암흑 지식(Dark Knowledge) — 정보의 출처

```text
정답 라벨(하드 타깃)          교사의 출력 분포(소프트 타깃)
고양이  1.0                    고양이  0.90
개      0.0                    개      0.08
호랑이  0.0                    호랑이  0.019
자동차  0.0                    자동차  0.001
```

정답 라벨은 "고양이가 맞고 나머지는 다 틀렸다"만 말하고 **틀린 것들끼리는 전부 동등하게** 취급한다. 교사의 분포는 **"굳이 틀린다면 개 쪽이지 자동차는 절대 아니다"** 를 말해 준다.

Hinton은 이 정보를 **암흑 지식(dark knowledge)** 이라 불렀다. 정답에 가려 보이지 않지만 교사가 데이터에서 배운 **구조**가 여기 들어 있다.

> 🏫 **비유**: 시험 답안지에 정답만 적힌 것과, **오답 선지마다 "이건 아깝게 틀렸고 저건 완전히 엉뚱하다"는 선생님 코멘트가 달린 것**의 차이다. 정보의 출처는 같지만 **전달 밀도**가 다르다.

**그래서 부수 효과가 둘 따라온다.**

| 효과 | 이유 |
|---|---|
| **적은 데이터로도 학습된다** | 예시당 학습 신호가 훨씬 풍부하다 |
| **일반화가 좋아진다** | 소프트 타깃이 학생을 과도하게 확신하지 않게 만든다 (레이블 스무딩과 유사한 정규화 효과) |

### 심화: 온도 — 같은 수식, 정반대의 목적

| | 온도의 용도 |
|---|---|
| **텍스트 생성** | 출력의 **다양성**을 조절 (`T↑` → 창의적, `T↓` → 결정적) |
| **지식 증류** | 교사에게서 **정보를 더 뽑아내기** (`T↑` → 숨은 유사 관계가 학습 신호가 됨) |

**같은 수식(`softmax(z/T)`)이 쓰이는 자리에 따라 전혀 다른 문제를 푼다** — [[2026-08-28-ai-data-temperature-sampling]]

그리고 "학습 신호가 된다"는 표현이 정확한 이유는 [[2026-09-01-ai-data-svm]]의 힌지 손실과 같은 구조이기 때문이다. **손실에 기여하지 않는 값은 기울기가 0이라 학습에 아무 영향을 주지 않는다.** SVM에서 마진 밖 점들이 무시됐던 것과 정확히 같다.

### 심화: 손실 함수 — 두 스승을 함께 따른다

```text
L = α · CE(학생, 정답 라벨)  +  (1 − α) · T² · KL(학생 ‖ 교사)
        └──────────────┘           └──────────────────┘
          하드 손실                     소프트 손실
        "정답을 맞혀라"              "교사를 흉내 내라"
```

| 항 | 역할 |
|---|---|
| **하드 손실** | 정답 라벨과의 교차 엔트로피(Cross-Entropy). **교사가 틀렸을 때 학생이 함께 틀리는 걸 막는다** |
| **소프트 손실** | 교사 분포와의 KL 발산(Kullback-Leibler Divergence). 암흑 지식을 옮긴다 |
| **α** | 둘의 균형을 잡는 하이퍼파라미터 → [[2026-08-31-ai-data-hyperparameter-tuning]] |
| **T²** | 온도를 올리면 기울기가 `1/T²`로 작아지므로 스케일을 되돌린다 |

이 손실이 역전파를 타고 학생 가중치로 흐른다. **증류는 새로운 학습 알고리즘이 아니라 손실 함수를 바꾼 것뿐이다** — [[2026-09-04-ai-data-backpropagation]]

### 심화: LLM 증류 세 방식과 압축 기법 비교

| 방식 | 무엇을 맞추나 | 특징 |
|---|---|---|
| **로짓 증류** | 교사의 출력 확률 분포 | 고전적. 교사의 로짓에 접근 가능해야 함 |
| **특징 증류** | 중간 층의 은닉 표현까지 | 더 촘촘한 신호. DistilBERT·TinyBERT |
| **데이터/시퀀스 증류** | 교사가 **생성한 텍스트** | **오늘날 LLM에서 가장 흔함**. Alpaca·Vicuna 계열 |

**DistilBERT**: 파라미터 약 **40% 감소**, 추론 속도 약 **60% 향상**, 언어 이해 능력 약 **97% 유지**.

**다른 압축 기법과의 비교**

| 기법 | 방식 | 성격 |
|---|---|---|
| **증류** | 작은 모델을 **새로 학습**시킨다 | 구조를 자유롭게 바꿀 수 있다. 재학습 필요 |
| **양자화** | 가중치 **정밀도를 낮춘다**(FP16 → INT8/INT4) | 구조 그대로. 학습 없이도 가능 → [[2026-09-02-ai-data-kv-cache]] |
| **가지치기**(Pruning) | 중요도 낮은 **가중치를 제거** | 희소해져 실제 속도 이득에 하드웨어 지원이 필요 |

**셋은 배타적이지 않다.** 증류한 학생을 다시 양자화하는 식으로 겹쳐 쓴다.

### 심화: 기술 장벽이 사라진 자리를 계약이 메운다

```text
로짓·특징 증류  →  교사의 내부가 필요 → 보통 자기가 가진 모델로 한다
데이터 증류     →  출력 텍스트만 필요 → 남의 서비스를 통해서도 된다
                                          ↑
                                  여기에 이용약관이 붙어 있다
```

API로 텍스트를 받는 것은 **정상적인 사용과 구분되지 않는다.** 그래서 제공자는 기술로 차단하는 대신 **약관에 "출력물로 경쟁 모델을 학습시키지 말 것"을 넣는다.** 물리적 장벽이 없으니 법적 장벽을 세우는 것이다.

그리고 **탐지가 어렵다**는 문제가 뒤따른다. 그래서 출력에 **워터마킹**을 넣거나 **카나리 문자열**을 심는 논의가 나온다.

### 이전 학습과의 연결

- [[2026-08-28-ai-data-temperature-sampling]] — **같은 온도 수식이 정반대 목적**으로 쓰인다. 생성에서는 다양성 조절, 증류에서는 정보 추출.
- [[2026-09-04-ai-data-backpropagation]] — 증류의 손실이 역전파를 타고 학생에게 흐른다. **"손실에 기여하지 않으면 기울기가 0"** 이 온도가 필요한 이유의 근거다.
- [[2026-09-01-ai-data-svm]] — 힌지 손실에서 마진 밖 점이 무시되는 것과, `T=1`에서 작은 확률이 무시되는 것이 **같은 구조**다.
- [[2026-09-02-ai-data-kv-cache]] — **양자화**가 두 노트에 걸쳐 등장한다. KV 캐시에서는 캐시 메모리 절감용, 여기서는 모델 압축 기법의 하나로.
- [[2026-08-04-ai-data-classification-metrics]] — 소프트맥스 출력을 확률 분포로 읽는 관점이 이어진다.
- [[2026-08-31-ai-data-hyperparameter-tuning]] — `α`와 `T`가 튜닝 대상이다. 둘 다 로그 스케일 탐색이 적합한 종류다.
- [[2026-07-22-ai-data-what-is-an-llm]] — 큰 모델을 실제로 배포하려면 압축이 필요하다는 실무 맥락이 여기서 구체화된다.
