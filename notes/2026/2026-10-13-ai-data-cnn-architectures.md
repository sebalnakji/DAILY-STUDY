## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 전체 흐름 — 세 막

```text
1막  더 깊게           AlexNet (2012) → VGG (2014)
                       "깊을수록 좋다"
         ↓
2막  깊으면 막힌다      Inception (2014) → ResNet (2015) → DenseNet (2017)
     → 어떻게 뚫나      "깊게 쌓을 수 있는 구조를 만들자"
         ↓
3막  가볍게            SqueezeNet (2016) → MobileNet·Xception (2017) → EfficientNet (2019)
                       "같은 성능을 적은 계산으로"
```

**각 아키텍처는 앞 단계가 남긴 문제에 대한 답이다.** 이 흐름으로 기억하면 이름이 저절로 자리를 찾는다.

### 1막 — 더 깊게

#### AlexNet (2012) — 딥러닝의 출발 신호

ImageNet 대회에서 **top-5 오류율 약 15.3%** 로 2위(약 26.2%)를 **10%p 넘게** 앞질렀다. 8층, 약 6천만 파라미터.

**구조보다 "도구 조합"이 핵심**이었다 — 지금까지 배운 것들이 여기서 한꺼번에 등장한다.

| 도구 | 역할 | 관련 노트 |
|---|---|---|
| **ReLU** | 시그모이드 대신 써서 기울기 소실을 줄이고 학습을 빠르게 | [[2026-09-03-ai-data-activation-functions]] |
| **드롭아웃** | 완전연결층의 과적합 억제 | [[2026-09-16-ai-data-dropout]] |
| **데이터 증강** | 크롭·반전·PCA 색 증강 | [[2026-10-07-ai-data-augmentation-rotation]] |
| **GPU 학습** | 큰 모델을 현실적인 시간에 학습 | — |

#### VGG (2014) — 3×3만 반복해서 깊게

**모든 합성곱을 3×3으로 통일**하고 16~19층까지 쌓았다. 구조가 단순해 이해와 재사용이 쉽다.

**왜 큰 필터 대신 3×3을 여러 번 쌓나**

```text
3×3 두 번 쌓기  = 5×5 한 번과 같은 범위를 본다 (수용 영역 5×5)

파라미터(입출력 채널 C 기준)
  5×5 한 번   : 25·C²
  3×3 두 번   : 2 × 9·C² = 18·C²     ← 약 28% 적다

비선형
  5×5 한 번   : 활성화 함수 1번
  3×3 두 번   : 활성화 함수 2번       ← 표현력이 더 크다
```

**같은 범위를 보면서 파라미터는 적고 비선형은 많다.** 7×7 하나는 3×3 세 번으로 대신한다(49·C² vs 27·C²).

**약점**: 약 **1억 3,800만 파라미터**, 그중 **대부분이 끝의 완전연결층**에 몰려 있다. 무겁고 느리다. 그리고 VGG 이후로 **20층 이상을 쌓으면 오히려 성능이 떨어지는** 벽에 부딪힌다 → 2막.

### 2막 — 깊으면 막힌다, 어떻게 뚫나

#### Inception / GoogLeNet (2014) — 넓게, 그리고 1×1로 줄여서

**아이디어 ① 여러 크기를 동시에**: 한 층에서 1×1, 3×3, 5×5 합성곱과 풀링을 **나란히** 돌리고 결과를 이어 붙인다. 어떤 크기의 패턴이 중요할지 미리 정하지 않고 **모델이 고르게** 한다.

**아이디어 ② 1×1 합성곱으로 채널 줄이기(병목, bottleneck)**: 5×5를 바로 하면 비싸다. 먼저 **1×1 합성곱으로 채널 수를 줄인 뒤** 큰 합성곱을 한다.

```text
입력 256채널 → 5×5 합성곱 → 출력 256채널     : 5·5·256·256 ≈ 164만 곱셈 (위치당)
입력 256채널 → 1×1로 64채널 → 5×5 → 256채널 : 1·1·256·64 + 5·5·64·256 ≈ 43만    ← 약 1/4
```

**1×1 합성곱은 공간은 그대로 두고 채널만 섞고 줄이는 장치**다. 이후 거의 모든 아키텍처가 이 기법을 쓴다. GoogLeNet은 22층인데도 파라미터가 **약 700만** 수준으로 VGG의 1/20에 가깝다.

**Inception v3**는 여기에 **필터 분해**를 더했다 — 5×5를 3×3 두 번으로(VGG의 발상), `n×n`을 `1×n` + `n×1`로 쪼개 계산을 더 줄인다.

#### ResNet (2015) — 잔차 연결로 깊이의 벽을 깨다 ⭐

**발견된 문제 — 성능 저하(degradation)**

```text
일반 CNN 20층  : 훈련 오차  낮음
일반 CNN 56층  : 훈련 오차  더 높음  ← 과적합이 아니다!
```

**과적합이라면 훈련 오차는 낮고 검증 오차만 높아야 한다.** 그런데 56층은 **훈련 오차 자체가 더 높았다.** 더 큰 모델이 **훈련 데이터조차 못 맞춘 것** — 표현력이 아니라 **최적화(학습)의 문제**다.

**무엇을 원하는 상황인가**

56층이 20층보다 나빠지지 않으려면, **남는 36층은 입력을 그대로 통과**시키면 된다. 즉 이 층들의 **목표 출력은 입력과 똑같은 값**이다.

```text
목표: 입력 x = [3, 5]  →  출력 y = [3, 5]
```

**일반 층 `y = F(x)` — 출발점이 정답에서 멀다**

출력이 `F(x)` 하나뿐이니 **`F(x) = x`** 를 배워야 한다. `[3, 5]`를 넣어 정확히 `[3, 5]`가 나오려면 가중치가 정확히 이래야 한다.

```text
W = [[1, 0],
     [0, 1]]       ← 대각선은 정확히 1, 나머지는 정확히 0
```

그런데 학습은 **0 근처의 작은 무작위 값에서 출발**한다([[2026-09-10-ai-data-weight-initialization]]). 처음엔 `[3, 5]`를 넣어도 엉뚱한 값이 나오고, 거기서 이 정확한 값까지 찾아가야 한다. 36개 층이 모두 동시에. **그래서 어렵다.**

**잔차 블록 `y = F(x) + x` — 출발점이 이미 정답 근처**

```text
F(x) + x = x
      F(x) = 0        ← 양변에서 x를 빼면 이것만 남는다
```

**`F`는 "0을 내보내기"만 배우면 된다.** 0을 내보내려면 가중치가 0 근처면 되는데, **초기화가 이미 0 근처**다. 학습을 하나도 안 한 상태에서도:

```text
x    = [3, 5]
F(x) = [0.01, −0.02]           ← 초기 가중치가 작으니 F의 출력도 작다
y    = F(x) + x = [3.01, 4.98]  ← 이미 거의 그대로 통과하고 있다
```

| | 배워야 할 것 | 출발점(초기 가중치 ≈ 0)에서 |
|---|---|---|
| **일반 층** | `F(x) = x` (정확한 복사) | **멀다** |
| **잔차 블록** | `F(x) = 0` | **이미 거의 도착** |

> 🏫 **비유**: 일반 층은 원본 그림을 **백지에 처음부터 똑같이 다시 그리는** 일이다. 잔차 블록은 원본 위에 **투명 필름을 덧대고 고칠 부분만** 그리는 일이다. 고칠 게 없으면 **아무것도 안 그리면** 끝난다.

그래서 **층을 더 쌓아도 최소한 손해는 보지 않는다.** 쓸모없는 층은 `F ≈ 0`으로 사실상 꺼지고, 쓸모 있는 층만 입력을 조금씩 고친다. 그리고 [[2026-09-04-ai-data-backpropagation]]에서 본 대로 **덧셈 경로로 기울기가 곱셈을 우회해 흐른다.**

**결과**: **152층**으로 ImageNet 2015 우승(top-5 오류율 약 **3.57%**). 이후 **트랜스포머의 잔차 연결**도 이 발상을 그대로 쓴다 → [[2026-10-12-ai-data-layer-norm]]

#### DenseNet (2017) — 더하지 말고 이어 붙이기

ResNet이 `F(x) + x`로 **더한다면**, DenseNet은 **앞의 모든 층 출력을 이어 붙여(concat)** 다음 층에 넘긴다. 앞에서 뽑은 특징을 **재사용**하므로 층마다 새로 만들 채널이 적어도 되고, **파라미터가 적다.** 대신 이어 붙인 특징 맵을 들고 있어야 해서 **메모리를 많이 쓴다.**

### 3막 — 가볍게

깊이의 벽을 넘자, 이번엔 **폰·엣지 기기에서 돌릴 수 있게** 만드는 게 과제가 됐다. 레포가 "마지막 셋은 엣지 AI에 유용하다"고 한 부분이다.

#### SqueezeNet (2016) — 1×1로 짜내기

**AlexNet 수준 정확도를 파라미터 약 1/50로**(약 120만) 달성. Inception의 1×1 병목을 극단까지 밀어붙인 **Fire 모듈**(1×1로 압축 → 1×1·3×3으로 확장)을 쓴다.

#### MobileNet (2017) · Xception (2017) — 깊이별 분리 합성곱 ⭐

**표준 합성곱은 출력 한 칸을 만들 때 두 가지 일을 한꺼번에 한다.**
- **공간 패턴 찾기**: 3×3 주변을 보고 모양을 찾는다
- **채널 섞기**: 여러 입력 채널(예: R·G·B)의 정보를 합친다

**깊이별 분리 합성곱(depthwise separable convolution)은 이 둘을 나눈다.**

| 단계 | 하는 일 |
|---|---|
| **① 깊이별(depthwise)** | 입력 채널마다 **자기 전용 3×3 필터 하나**로 **공간 패턴만** 찾는다. 채널끼리는 섞지 않는다 |
| **② 점별(pointwise)** | **1×1 합성곱**으로 같은 위치의 **채널들만 섞어** 출력 채널을 만든다. 공간은 보지 않는다 |

**작은 숫자로 직접 세기** — 입력 3채널 → 출력 4채널, 필터 3×3, 출력 한 칸당 곱셈 수

```text
표준 합성곱
  출력 채널 1개 = 3 × 3 × 3(입력 채널) = 27번
  출력 채널 4개 = 27 × 4             = 108번
  → 출력 채널마다 공간 찾기와 채널 섞기를 처음부터 다시 한다

깊이별 분리 합성곱
  ① 깊이별 : 채널당 3 × 3 = 9번 × 입력 채널 3개 = 27번   (결과: 여전히 3채널)
  ② 점별   : 출력 채널당 입력 3개를 섞음 = 3번 × 출력 4개 = 12번
  합계 27 + 12 = 39번                                      → 약 1/2.8
```

**채널이 많으면 차이가 커진다** — 입력 256 → 출력 256

```text
표준 : 9 × 256 × 256        = 589,824번
분리 : 9 × 256 + 256 × 256  =   2,304 + 65,536 = 67,840번
비율 ≈ 1/8.7  →  약 8~9배 감소
```

**왜 줄어드나 — 곱이 합으로 바뀐다**

```text
표준 : 공간(9) × 입력 채널(M) × 출력 채널(N)          ← 세 수의 곱
분리 : 공간(9) × 입력 채널(M)  +  입력(M) × 출력(N)    ← 두 곱의 합
비율 = (9M + MN) / (9MN) = 1/N + 1/9  → 채널이 많으면 약 1/9
```

표준 합성곱은 **"이 공간 위치 × 이 입력 채널 × 이 출력 채널"의 모든 조합**마다 가중치를 따로 둔다. 분리 합성곱은 공간 일과 채널 일을 따로 하므로 곱이 합으로 바뀌고, 채널이 많을수록 절약이 커진다.

> 🏫 **비유**: 요리 네 가지를 만든다. **표준**은 요리마다 **재료 손질부터 처음부터** 다시 한다. **분리**는 재료를 **한 번씩만 손질**해 두고(①), 요리마다 **손질된 재료를 섞기만** 한다(②).

**MobileNet**은 이걸로 폰에서 돌아가는 CNN을 만들었고, **Xception**은 "Inception을 극단으로 밀면 이것"이라는 관점에서 같은 연산을 쓴다(이름이 Extreme Inception).

#### EfficientNet (2019) — 세 방향을 함께 키우기

모델을 키우는 방법은 세 가지다 — **깊이**(층 수), **너비**(채널 수), **해상도**(입력 크기). 이전에는 하나만 크게 키웠다(ResNet은 깊이).

EfficientNet은 **세 가지를 정해진 비율로 함께** 키운다(**복합 스케일링, compound scaling**). 해상도가 커지면 더 넓은 범위를 봐야 하니 깊이가 필요하고, 더 세밀한 패턴이 생기니 너비도 필요하다 — **셋은 서로 맞물려 있다.** 그 결과 **같은 정확도를 훨씬 적은 파라미터와 계산으로** 달성했다.

## 기준 답변

### 한 장 요약표

| 아키텍처 | 연도 | 풀려던 문제 | 핵심 아이디어 |
|---|---|---|---|
| **AlexNet** | 2012 | 딥러닝이 되는가 | ReLU·드롭아웃·증강·GPU |
| **VGG16** | 2014 | 더 깊게 | **3×3만 반복** — 같은 범위, 적은 파라미터, 많은 비선형 |
| **Inception v3** | 2014~15 | 깊고 넓게, 그러나 싸게 | 여러 크기를 나란히, **1×1 병목**, 필터 분해 |
| **ResNet** | 2015 | 깊으면 **훈련 오차가 오른다** | **잔차 연결** `F(x) + x` |
| **DenseNet** | 2017 | 특징 재사용 | 앞의 모든 출력을 **이어 붙임** |
| **SqueezeNet** | 2016 | 작게 | Fire 모듈 — AlexNet급을 **1/50 파라미터로** |
| **MobileNet** | 2017 | 폰에서 돌리기 | **깊이별 분리 합성곱** — 계산 약 1/9 |
| **Xception** | 2017 | Inception의 극단 | 깊이별 분리 합성곱 |
| **EfficientNet** | 2019 | 어떻게 키울까 | **깊이·너비·해상도 복합 스케일링** |

### 실무에서는

이 아키텍처들은 대부분 **사전학습된 백본(backbone)** 으로 쓰인다. 직접 만들기보다 ImageNet으로 학습된 가중치를 가져와 [[2026-09-17-ai-data-transfer-learning]]으로 내 과제에 맞춘다.

| 상황 | 선택 |
|---|---|
| 무난한 기준선 | **ResNet-50** |
| 정확도·효율 균형 | **EfficientNet** |
| 모바일·엣지 | **MobileNet** 계열 |
| 구조를 이해·교육용으로 | **VGG** |

> 💡 오늘날 이미지 분야에는 **ViT**(Vision Transformer)도 널리 쓰인다. [[2026-09-11-ai-data-cnn]]에서 본 대로 데이터가 아주 많으면 ViT, 적으면 CNN이 유리한 경향이 있다.

### 한 문장 요약

> **CNN 아키텍처의 역사는 "더 깊게(AlexNet·VGG) → 깊으면 훈련조차 안 되는 문제를 잔차로 해결(Inception의 1×1 병목, ResNet, DenseNet) → 같은 성능을 가볍게(SqueezeNet, MobileNet·Xception의 깊이별 분리 합성곱, EfficientNet의 복합 스케일링)"의 세 막이다. 각 아키텍처는 앞 단계가 남긴 문제에 대한 답이다.**

## 내가 정리한 내용

### 1. VGG가 3×3을 여러 번 쌓는 이유

같은 범위를 보면서 —
- **① 파라미터가 적다**: 3×3 두 번은 `18·C²`, 5×5 한 번은 `25·C²` → 약 28% 적다.
- **② 비선형이 많다**: 활성화 함수를 두 번 거쳐 표현력이 좋다.

### 2. ResNet이 해결한 문제와 잔차 연결

- **과적합이 아니라 오히려 학습이 안 되는 문제**다. 깊은 모델이 훈련 오차조차 더 높았다.
- 남는 층이 입력을 그대로 내보내면 되는데, 일반 층 `y = F(x)`는 **`F(x) = x`를 배워야** 한다. 작은 무작위 가중치에서 출발하면 출력이 입력과 전혀 다른 값이 나오므로, **입력을 정확히 복사하는 가중치(대각선 1, 나머지 0)** 를 찾아가야 한다 — **출발점이 정답에서 멀다.**
- 잔차 블록 `y = F(x) + x`에서는 목표가 **`F(x) = 0`을 배우는 것**이 되고, 초기 가중치가 이미 0에 가까워 **출발점이 이미 정답 근처**다. 그래서 쉽게 통과되고, 층을 더 쌓아도 **최소한 손해는 보지 않는다.**

### 3. 깊이별 분리 합성곱

- 표준 합성곱의 일을 **공간 패턴 찾기**와 **채널 섞기**로 나눈다.
  - **① 깊이별**: 입력 채널마다 자기 전용 3×3 필터 하나로 **공간 패턴만** 찾는다. 채널은 섞지 않는다.
  - **② 점별**: 1×1 합성곱으로 같은 위치의 **채널들만 섞는다.** 공간은 보지 않는다.
- 표준 합성곱은 **"공간 위치 × 입력 채널 × 출력 채널"의 모든 조합**마다 가중치를 따로 둔다. 분리 합성곱은 공간 일과 채널 일을 따로 하니까 **세 수의 곱이 두 곱의 합으로** 바뀐다. 256채널 → 256채널이면 **약 8~9배** 줄어든다.

## 검토 결과

### 확인된 부분

- ResNet이 푼 문제를 **과적합이 아니라 학습(최적화)의 문제**로 정확히 구분했다.
- 잔차 블록의 핵심을 **"초기 가중치가 이미 0 근처라 `F(x) = 0`이 쉽다"** 는 **출발점**의 관점으로 설명했다.
- 깊이별 분리 합성곱이 계산을 줄이는 이유를 **"곱이 곱의 합으로 바뀐다"** 로 정확히 잡았다.
- 설명이 부족한 지점(잔차 식, 분리 합성곱)을 **모르겠다고 분명히 짚고** 다시 물었다.

### 보강 포인트

#### ① 처음 설명이 부실했다 — 기준 답변을 대화 중 보강함

처음 쓴 ResNet·깊이별 분리 합성곱 설명은 **식과 결론만 있고 중간 과정이 빠져** 있었다(사용자 피드백). 대화에서 **목표(`y = x`) → 일반 층이 어려운 이유 → 잔차가 바꾸는 것**, **3→4채널로 직접 세기 → 256채널 비교** 순서로 다시 설명했고, 위 `핵심 개념`의 두 절을 그 설명으로 바꿨다.

#### ② "뒤죽박죽"은 정확한 표현이 아니다

| | 내용 |
|---|---|
| **전** | `y = F(x)`이면 **위치가 뒤죽박죽**이라 입력이 유지되기 힘들다 |
| **후** | **`F(x) = x`를 배워야** 하는데, 초기 출력이 입력과 전혀 달라 **출발점이 정답에서 멀다** |

뒤죽박죽인 것은 위치가 아니라 **무작위 가중치로 만든 초기 출력값**이다. 그리고 `F(x) = 0`은 "해 놓는" 게 아니라 그렇게 되도록 **학습하는** 것이다.

#### ③ 질문의 앞부분을 건너뛰었다

깊이별 분리 합성곱 질문은 **"각 단계가 무엇을 하는지" 그리고 "왜 계산이 줄어드는지"** 두 부분이었는데, 뒤쪽만 답했다. **질문에 "그리고"가 있으면 답도 두 덩어리인지** 확인하는 습관이 필요하다.

#### ④ VGG 이유는 두 가지로 나눠 말하기

"같은 범위·적은 파라미터·많은 비선형"을 한 문장으로 썼다. 질문이 **두 가지 이유**를 물었으므로 **① 파라미터 ② 비선형**으로 나누고 숫자(`18·C²` vs `25·C²`)를 붙이면 분명해진다.

### 심화: 세 막의 흐름으로 기억하기

```text
1막  더 깊게      AlexNet → VGG          "3×3을 쌓으면 깊게 갈 수 있다"
2막  깊으면 막힘  Inception → ResNet      "학습이 막히는 벽을 1×1과 잔차로 뚫는다"
3막  가볍게      MobileNet → EfficientNet "같은 성능을 적은 계산으로"
```

**각 아키텍처는 앞 단계가 남긴 문제에 대한 답이다.** 이름을 외우기보다 **"무엇을 풀려고 나왔나"** 를 기억하면 면접에서 순서대로 이야기할 수 있다.

### 심화: 1×1 합성곱이 세 번 등장한다

| 어디서 | 역할 |
|---|---|
| **Inception** | 큰 합성곱 전에 **채널 줄이기(병목)** — 계산 약 1/4 |
| **SqueezeNet** | Fire 모듈에서 **압축** |
| **MobileNet** | 점별 단계에서 **채널 섞기** |

**공간은 그대로 두고 채널만 다루는 장치**라는 한 가지 성질이 세 아키텍처의 핵심 부품이 됐다.
