## 질문

>

## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 왜 필요한가 — 셀프 어텐션은 순서를 모른다

셀프 어텐션은 **모든 토큰을 동시에** 보고, 각 토큰 쌍의 관련도를 내적으로 계산한다. 이 연산에는 **위치 정보가 전혀 들어가지 않는다.** → [[2026-08-06-ai-data-self-attention]]

```text
"철수가 영희를 좋아한다"
"영희가 철수를 좋아한다"
   → 토큰 집합이 같아 어텐션 결과가 동일해진다
```

이 성질을 **순열 불변성(permutation invariance)** 이라 한다. 토큰 순서를 섞어도 결과가 같다는 뜻이다.

> **언어에서 순서는 의미 그 자체다.** 그래서 순서 정보를 따로 주입해야 한다.

### RNN과의 대비

- **RNN(Recurrent Neural Network)** 은 토큰을 **하나씩 순서대로** 처리했다. 순서가 **구조에 내장**되어 있어 위치 정보가 따로 필요 없었다.
- **Transformer는 병렬 처리를 얻는 대가로 순서를 잃었다.** 병렬 처리가 곧 학습 속도이므로 좋은 거래였고, 잃어버린 순서는 위치 인코딩으로 보충한다.

### 무엇인가

**각 토큰의 임베딩에 "그 토큰이 몇 번째인지"를 나타내는 벡터를 더해주는 것.**

```text
입력 = 토큰 임베딩 + 위치 인코딩
```

- 임베딩과 **같은 차원**의 벡터를 만들어 **더한다**(concat이 아니라 add).
- 이렇게 하면 같은 단어라도 **위치가 다르면 다른 입력 벡터**가 되어, 어텐션이 순서를 구분할 수 있다.

### 방식 ① 사인·코사인 (Sinusoidal, 원 논문)

서로 다른 주파수의 사인·코사인 함수로 위치 벡터를 만든다.

```text
PE(pos, 2i)   = sin( pos / 10000^(2i/d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) )
```

- 차원마다 **주파수가 다르다.** 낮은 차원은 빠르게 진동하고, 높은 차원은 느리게 진동한다.
- **학습이 필요 없다**(고정값).
- **학습 때 본 것보다 긴 시퀀스에도 외삽(extrapolation)** 이 가능하다는 점이 설계 의도였다.
- 상대적 위치가 **선형 변환으로 표현 가능**하다는 성질이 있다.

### 방식 ② 학습된 위치 임베딩 (Learned)

- 위치마다 벡터를 **파라미터로 두고 학습**한다(BERT, GPT-2 등).
- 구현이 단순하고 성능이 좋지만, **학습 때 정한 최대 길이를 넘어서면 쓸 수 없다.**

### 방식 ③ RoPE (Rotary Position Embedding) — 현대 LLM의 주류

- 위치 정보를 **더하는 대신 Q와 K를 회전**시킨다.
- 두 토큰의 어텐션 점수가 **상대적 거리에만 의존**하게 만드는 것이 핵심.
- **긴 문맥으로의 확장이 상대적으로 용이**해 LLaMA 등 최신 모델이 채택.

### 절대 위치 vs 상대 위치

| | 절대 위치 | 상대 위치 |
|---|---|---|
| 표현 | "이 토큰은 5번째" | "이 토큰은 저 토큰보다 3칸 뒤" |
| 예 | Sinusoidal, Learned | RoPE, ALiBi, T5 relative bias |
| 장점 | 단순 | **긴 문맥·외삽에 유리** |

언어에서 중요한 것은 대개 **절대 위치보다 상대적 거리**다("바로 앞 단어", "3칸 뒤"). 그래서 최신 모델이 상대 위치 계열로 이동했다.

### 왜 concat이 아니라 add인가

- concat하면 차원이 늘어나 **계산량이 커진다.**
- 임베딩 차원이 충분히 크면, 모델이 **위치 성분과 의미 성분을 분리해 사용하도록 학습**할 수 있다.
- 실용적으로 add가 잘 작동해 표준이 되었다.

## 기준 답변

> ⚠️ 이 기준 레포는 질문에 대해 텍스트 답변 대신 외부 글 링크를 제공한다. 아래는 표준적인 Transformer 개념을 바탕으로 재구성한 답변이다.

**위치 인코딩은 각 토큰의 임베딩에 그 토큰의 위치 정보를 담은 벡터를 더해주는 장치**다.

필요한 이유는 **셀프 어텐션이 순서를 모르기 때문**이다. 어텐션은 모든 토큰을 동시에 보고 토큰 쌍의 관련도만 계산하므로, 토큰의 순서를 바꿔도 결과가 같다(순열 불변성). 그래서 `"철수가 영희를 좋아한다"`와 `"영희가 철수를 좋아한다"`를 구분할 수 없다. 언어에서 순서는 의미 그 자체이므로 순서 정보를 따로 주입해야 한다.

RNN은 토큰을 하나씩 순서대로 처리해 순서가 구조에 내장되어 있었지만, **Transformer는 병렬 처리를 얻는 대가로 순서를 잃었고** 이를 위치 인코딩으로 보충한다.

원 논문은 서로 다른 주파수의 **사인·코사인 함수**로 위치 벡터를 만들었다. 학습이 필요 없고, 학습 때 본 것보다 긴 시퀀스로도 외삽이 가능하도록 설계되었다. 이후 **학습된 위치 임베딩**(BERT, GPT-2)도 널리 쓰였으나 최대 길이를 넘어설 수 없다는 한계가 있다.

최근 LLM은 **RoPE(Rotary Position Embedding)** 를 주로 쓴다. 위치 정보를 더하는 대신 Query와 Key를 회전시켜, 어텐션 점수가 **두 토큰의 상대적 거리에만 의존**하도록 만든다. 이 방식이 **긴 문맥으로 확장하기에 유리**하기 때문이다.

## 내가 정리한 내용

**1. 위치 인코딩이 왜 필요한가**

문장에서 문맥을 파악하는 것이 중요한데, Transformer는 토큰을 **한 번에 읽어** 장거리 의존성 해결과 병렬 처리(속도)를 얻는 대신 **순서를 잃었다.** 어텐션은 토큰 쌍의 관련도만 계산해 순서를 바꿔도 결과가 같으므로(순열 불변성), 순서를 알려주는 위치 인코딩이 필요하다.

**2. 어떤 방식들이 있는가**

- **절대 위치 — 사인·코사인**(원 논문): 서로 다른 주파수의 삼각함수로 위치 벡터를 만든다. **학습이 필요 없고 최대 길이 제약도 없다.**
- **절대 위치 — 학습된 임베딩**(BERT, GPT-2): 위치마다 벡터를 학습한다. 단순하고 성능이 좋지만 **학습 때 정한 최대 길이를 넘어서면 쓸 수 없다.**
- **상대 위치 — RoPE, ALiBi**: 절대 좌표 대신 **토큰 간 상대적 거리**로 인코딩한다. RoPE는 위치를 더하는 대신 **Q와 K를 회전**시켜 어텐션 점수가 상대 거리에만 의존하게 만든다.

**3. 왜 상대 위치로 옮겨갔는가**

첫째, **언어에서 중요한 것은 절대 위치가 아니라 상대적 거리**이기 때문이다. 문장이 문서의 몇 번째에서 시작하든 어법은 동일하다.

둘째, **긴 문맥으로의 확장에 유리**하기 때문이다. "3칸 뒤"라는 관계는 위치가 100이든 10000이든 동일하게 해석되므로, 학습 때 본 것보다 긴 시퀀스에서도 안정적이다.

## 검토 결과

### 확인된 부분

- **"장거리 의존성 해결과 속도를 얻은 대신 순서를 잃었다"** 는 트레이드오프를 정확히 서술. Transformer 설계의 핵심 거래를 한 문장으로 압축했다.
- 실습 Q2(최대 길이 512 모델에 1000 토큰)를 정확히 판단.
- RNN이 위치 인코딩을 필요로 하지 않은 이유(순차 처리로 순서가 구조에 내장)를 정확히 파악.

### 보강 포인트

- ⚠️ **"최대 길이 제약"은 절대 위치 전체의 한계가 아니라 "학습된 임베딩"의 한계다.** (초기 답변에서 절대 위치 = 학습된 방식으로 혼동)

  | | 방식 | 최대 길이 제약 |
  |---|---|---|
  | **절대 ①** | **사인·코사인**(고정 수식) | ❌ **없음** — 오히려 외삽하라고 만든 것 |
  | **절대 ②** | **학습된 임베딩**(BERT, GPT-2) | ✅ **있음** — 학습 때 정한 길이가 벽 |
  | **상대** | RoPE, ALiBi | 확장 유리 |

  `PE(pos) = sin(pos / ...)` 는 `pos`에 아무 숫자나 넣어도 값이 나온다. 512든 5000이든 계산된다.

  > **"최대 길이 제약"은 절대/상대의 문제가 아니라, 위치 벡터를 미리 학습해뒀느냐의 문제다.**

- **Q3는 Q2 답변을 그대로 옮긴 상태였다 → 이유 두 가지로 확장.** "절대 위치의 문제를 극복"만으로는 *왜 상대가 더 나은지*를 설명하지 못한다.

### 심화: RNN vs Transformer가 얻고 잃은 것 (Q1)

```text
RNN:         t1 → t2 → t3 → t4 ...   순차적, 병렬 불가
Transformer: t1  t2  t3  t4          전부 동시에 ✅
```

**RNN이 느렸던 이유**: 5번째 토큰을 처리하려면 1~4번째가 먼저 끝나야 한다. 순서대로만 갈 수 있어 **GPU를 놀리게 된다.**

**속도만 얻은 게 아니다.** RNN에는 **장거리 의존성 문제**도 있었다 — 문장이 길어지면 앞쪽 정보가 뒤로 갈수록 희미해진다(기울기 소실). 어텐션은 **거리와 무관하게 직접 연결**하므로 이 문제도 함께 해결했다.

> **병렬 처리 + 장거리 의존성 해결을 얻고, 순서를 잃었다.** 아주 남는 거래였다.

### 심화: 컨텍스트 윈도우 한계의 두 가지 원인 ⭐

8/6에 "O(n²)이 컨텍스트 한계의 근본 이유"라고 배웠는데, **사실 원인이 두 개다.**

| 원인 | 성격 | 해결 방향 |
|---|---|---|
| **① O(n²) 계산량** | **비용**의 문제 — 길면 느리고 비쌈 | Flash Attention, 희소 어텐션 |
| **② 위치 인코딩의 표현 범위** | **가능/불가능**의 문제 — 아예 못 씀 | **RoPE, ALiBi** 등 외삽 가능한 방식 |

**②가 더 딱딱한 벽이다.** ①은 "느리지만 되긴 된다"이지만 ②는 "아예 안 된다"이기 때문.

> **"컨텍스트 32K 모델"이 나오려면 O(n²)을 감당하는 것뿐 아니라, 위치 인코딩이 32K를 표현할 수 있어야 한다.**

실제로 **position interpolation** 같은 기법으로 학습 후에 컨텍스트를 늘리기도 한다. → [[2026-08-06-ai-data-self-attention]]

### 사인·코사인의 직관

```text
PE(pos, 2i)   = sin( pos / 10000^(2i/d) )
PE(pos, 2i+1) = cos( pos / 10000^(2i/d) )
```

차원마다 **진동 속도가 다르다.** 낮은 차원은 빠르게, 높은 차원은 느리게 진동한다.

**시계 바늘 비유**: 초침·분침·시침이 함께 있으면 시각이 유일하게 특정되듯, 여러 주파수의 조합이 위치를 유일하게 표현한다.

### 왜 concat이 아니라 add인가

- **concat하면 차원이 늘어 계산량이 커진다.** 어텐션이 이미 O(n²)인데 차원까지 늘리면 부담이 커진다.
- 임베딩 차원이 충분히 크면 모델이 **위치 성분과 의미 성분을 알아서 분리해 사용하도록** 학습한다.
- 실용적으로 잘 작동해 표준이 되었다.

### 이전 학습과의 연결

- **8/6 셀프 어텐션에서 남겨둔 숙제.** "순서를 모른다 → 위치 인코딩으로 주입한다"의 구체적 방법. → [[2026-08-06-ai-data-self-attention]]
- **입력 파이프라인 위치**: `텍스트 → 토큰 → 임베딩 + 위치 인코딩 → 셀프 어텐션` → [[2026-07-29-ai-data-tokenization]], [[2026-08-03-ai-data-embeddings]]
- **RoPE가 Q·K를 회전시킨다**는 것은 8/6에 배운 Q·K가 관련도를 정한다는 구조 위에서 이해된다.
