## 질문

> **데이터셋에 결측치나 손상된 데이터가 있을 때 어떻게 처리하는가?**
>
> 원문: *How Do You Handle Missing or Corrupted Data in a Dataset*

## 핵심 개념

질문에 답하기 위해 필요한 핵심 개념을 정리한다.

### 0단계 — 왜 결측인지부터 파악한다

**처리 방법을 고르기 전에 결측의 원인을 봐야 한다.** 원인에 따라 올바른 처리가 달라진다.

| 유형 | 뜻 | 예시 |
|---|---|---|
| **MCAR** (Missing Completely At Random) | 완전 무작위 결측. 다른 어떤 변수와도 무관 | 센서가 우연히 고장 |
| **MAR** (Missing At Random) | **다른 관측된 변수**로 설명되는 결측 | 특정 연령대가 소득 응답을 자주 거부 |
| **MNAR** (Missing Not At Random) | **결측값 자체**에 이유가 있음 | 소득이 아주 높거나 낮은 사람이 답을 회피 |

- **MCAR**이면 삭제해도 편향이 거의 없다.
- **MNAR**이면 삭제하거나 단순 대치하면 **심각한 편향**이 생긴다. 이 경우 **결측이라는 사실 자체가 정보**다.

### 처리 방법 ① — 삭제(Deletion)

- **행 삭제(listwise deletion)**: 결측이 있는 행을 버린다. 간단하지만 **데이터 손실**이 크고 MCAR이 아니면 편향된다.
- **열 삭제**: 결측 비율이 지나치게 높은 열(예: 70% 이상)은 통째로 버리는 편이 낫다.

### 처리 방법 ② — 대치(Imputation)

| 방법 | 설명 | 주의 |
|---|---|---|
| **평균/중앙값** | 수치형에 사용. 이상치가 있으면 **중앙값**이 안전 | 분산이 줄어들고 상관관계가 왜곡됨 |
| **최빈값** | 범주형에 사용 | 최빈 범주가 과대 대표됨 |
| **앞/뒤 값 채우기** | 시계열에서 직전·직후 값 사용 | 시계열 외에는 부적절 |
| **KNN 대치** | 비슷한 이웃들의 값으로 채움 | 계산 비용이 큼 |
| **모델 기반 대치** | 다른 특징으로 결측값을 **예측**해 채움 | 가장 정교하지만 복잡 |

### 처리 방법 ③ — 결측 자체를 정보로 쓴다

- **결측 여부 플래그 특징 추가**: `income_is_missing` 같은 이진 특징을 만든다.
- **MNAR일 때 특히 유효하다.** "답하지 않았다"는 사실이 예측에 도움이 되는 경우가 많다.
- 범주형이면 `"Unknown"` 같은 **별도 범주**로 두는 것도 방법.

### 처리 방법 ④ — 모델에게 맡긴다

- **XGBoost, LightGBM, CatBoost는 결측치를 네이티브로 처리한다.** 분기할 때 결측값을 어느 쪽으로 보낼지 **학습으로 결정**한다.
- 별도 대치 없이 그대로 넣는 편이 나은 경우도 있다. → [[2026-08-05-ai-data-bias-variance]]

### 손상된(corrupted) 데이터

결측과 별개로 **잘못된 값**을 다뤄야 한다.

- **이상치(outlier)**: 도메인 기준이나 IQR·z-score로 탐지. **제거할지, 상한/하한으로 자를지(winsorizing), 그대로 둘지**는 문제에 따라 다르다.
- **타입 오류**: 숫자 컬럼에 문자열, 날짜 형식 불일치
- **범위 위반**: 나이가 −5 또는 999
- **중복 행**: 같은 레코드가 여러 번
- **인코딩 깨짐**: 한글이 깨진 문자열 → [[2026-07-29-ai-data-tokenization]]의 NFC/NFD 문제와 같은 계열

### ⚠️ 가장 중요한 함정 — 대치 기준은 train에서만 계산한다

전체 데이터의 평균으로 결측을 채우면 **test 정보가 학습에 새어 들어간다(데이터 누수).**

```python
imputer.fit_transform(X_train)   # fit(기준 학습) + transform  ← train에만
imputer.transform(X_test)        # transform만                 ← 기준은 train 것 재사용
```

→ [[2026-07-31-ai-data-ml-lifecycle]]의 전처리 누수와 정확히 같은 구조.

### 실무 순서

```text
① 결측 현황 파악 (컬럼별 비율, 패턴)
② 왜 결측인지 원인 추정 (MCAR / MAR / MNAR)
③ 결측 비율이 과도한 열은 제거 검토
④ 남은 결측은 대치 또는 결측 플래그 추가
⑤ 대치 기준은 train에서만 계산해 나머지에 적용
⑥ 처리 전후 성능을 검증으로 비교
```

## 기준 답변

> ⚠️ 이 기준 레포는 질문 목록만 제공하고 답변은 싣지 않는다. 아래는 표준적인 ML 실무 기준으로 재구성한 답변이다.

**먼저 결측의 원인을 파악한다.** 완전 무작위(MCAR)인지, 다른 변수로 설명되는지(MAR), 결측값 자체에 이유가 있는지(MNAR)에 따라 올바른 처리가 달라진다. MNAR인데 단순 삭제하거나 평균으로 채우면 **심각한 편향**이 생긴다.

**처리 방법**은 크게 네 가지다.

1. **삭제** — 결측이 있는 행을 버리거나, 결측 비율이 지나치게 높은 열을 통째로 제거한다. 간단하지만 데이터 손실이 크고 MCAR이 아니면 편향된다.
2. **대치** — 수치형은 평균이나 중앙값(이상치가 있으면 중앙값), 범주형은 최빈값으로 채운다. 시계열은 앞/뒤 값, 더 정교하게는 KNN이나 모델 기반 예측으로 채울 수 있다.
3. **결측 자체를 정보로 사용** — `is_missing` 플래그 특징을 추가하거나 `"Unknown"` 범주를 만든다. **MNAR에서 특히 유효하다.**
4. **모델에게 맡김** — XGBoost, LightGBM, CatBoost는 결측치를 네이티브로 처리하며, 분기 시 결측을 어느 쪽으로 보낼지 학습으로 결정한다.

**손상된 데이터**는 이상치, 타입 오류, 범위 위반, 중복 행, 인코딩 깨짐 등을 점검하고 도메인 기준에 따라 수정하거나 제거한다.

**가장 중요한 주의점은 대치 기준을 학습 데이터에서만 계산하는 것**이다. 전체 데이터의 평균으로 채우면 테스트 정보가 학습에 새어 들어가 **데이터 누수**가 발생한다.

## 내가 정리한 내용

**1. 처리 전 가장 먼저 확인할 것**

**결측이 MCAR / MAR / MNAR 중 어떤 유형인지 파악한다.** 유형에 따라 올바른 처리가 달라지기 때문이다.

- **MCAR**(완전 무작위): 삭제해도 편향이 거의 없다
- **MAR**(다른 변수로 설명됨)
- **MNAR**(결측값 자체에 이유가 있음): 삭제도 단순 대치도 **심각한 편향**을 만든다

**2. 처리 방법**

- **삭제** — 결측이 있는 행을 삭제하거나, 결측률이 높은 열을 통째로 제거
- **대치** — 수치형은 평균, **이상치가 있으면 중앙값**, 범주형은 **최빈값**, 시계열은 앞/뒤 값. 더 정교하게는 KNN이나 모델 기반 예측. 단, 같은 값으로 채우면 **분산이 줄고 상관관계가 왜곡**된다
- **결측 자체를 정보로 사용** — `is_missing` 플래그 특징을 추가하거나 `"Unknown"` 범주를 만든다. **MNAR에서 특히 유효**하다
- **모델에게 위임** — XGBoost, LightGBM, CatBoost는 결측치를 그대로 받아 **분기 방향을 학습으로 결정**한다

**3. 반드시 지켜야 할 것**

- 반드시 **결측 유형을 확인한 뒤 그에 맞는 처리**를 한다
- **대치 기준은 학습 데이터에서만 계산**해 검증·시험 데이터에 적용한다. 전체 데이터로 계산하면 **데이터 누수(Data Leakage)** 가 발생한다
- 결측과 별개로 **손상된 데이터**(이상치, 타입 오류, 범위 위반, 중복, 인코딩 깨짐)도 함께 점검한다

- 실습 Q2(데이터 누수)를 원칙과 용어 모두 정확히 답함.
- 실습 Q1에서 평균 대치의 편향 발생을 정확히 진단.

### 보강 포인트

- **Q1에 "어떻게 하는 게 나은지"(처방)가 누락**됐다가 보완됨. 진단만으로는 답이 닫히지 않는다.
- **유형 파악이 왜 먼저인지** 이유를 한 줄 붙이면 강해진다: 유형에 따라 올바른 처리가 달라지므로.
- **대치는 "언제 무엇을"과 부작용**을 함께 말할 것. 같은 값으로 채우면 **분산 축소 + 상관관계 왜곡**이 발생한다.

### 심화: MNAR에 평균 대치를 하면 (Q1)

```text
실제:    고소득자 3억, 3억, 2억 ...  (응답 안 함)
대치 후: 고소득자 5천, 5천, 5천 ...  (전부 평균)
```

**고소득자가 전부 평균으로 끌어내려진다.** 결과는 두 가지다.

- **소득의 분산이 실제보다 작아진다** — 데이터가 실제보다 균질해 보임
- **소득과 타깃의 관계가 약해진다** — 소득이 중요한 변수인데도 모델이 "별로 중요하지 않다"고 판단

무서운 점은 **조용히 일어난다**는 것이다. 에러도 없고 결측률 0%의 깨끗한 데이터로 보인다. → **숫자만 거짓말을 한다.** [[2026-07-30-ai-data-validation]]

**처방: 결측 자체를 특징으로 만든다**

```python
df['income_is_missing'] = df['income'].isna().astype(int)
```

이 플래그 하나가 **"이 사람은 고소득자일 가능성이 있다"** 를 모델에 전달한다. 정보를 버리는 대신 **살려내는** 것.

| 방법 | 설명 |
|---|---|
| **결측 플래그 추가** ⭐ | 가장 효과적. 결측 여부를 이진 특징으로 |
| **구간화(binning)** | 소득을 구간으로 나누고 **"무응답"을 별도 구간**으로 |
| **모델에 그대로** | XGBoost 계열은 결측을 학습으로 처리 |
| ❌ 평균/중앙값 대치 | **MNAR에서는 피한다** |

> **MCAR이면 채워도 되지만, MNAR이면 채우는 순간 정보가 사라진다.** 그래서 원인 파악이 먼저다.

### 손상된 데이터 — 결측과는 다른 문제

**결측은 비어 있는 것이고, 손상은 잘못 채워진 것이다.**

| 종류 | 예 |
|---|---|
| 이상치(outlier) | 도메인 기준이나 IQR·z-score로 탐지 |
| 타입 오류 | 숫자 컬럼에 문자열 |
| 범위 위반 | 나이가 `-5` 또는 `999` |
| 중복 행 | 같은 레코드가 여러 번 |
| 인코딩 깨짐 | 한글 깨짐 → [[2026-07-29-ai-data-tokenization]]의 NFC/NFD와 같은 계열 |

⚠️ **이상치는 "제거"가 항상 답이 아니다.** 사기 탐지에서는 **이상치가 곧 찾으려는 대상**이다. 도메인이 결정한다. → [[2026-08-04-ai-data-classification-metrics]]

### 대치 누수 방지 (Q2)

```python
imputer.fit_transform(X_train)   # fit(기준 학습) + transform  ← train에만
imputer.transform(X_test)        # transform만                 ← train 기준 재사용
```

전체 데이터의 평균/중앙값으로 채우면 **test 정보가 학습에 새어 들어간다.** 실전에서는 미래 데이터의 통계를 알 수 없다. → [[2026-07-31-ai-data-ml-lifecycle]]

```text
① 결측 현황 파악 (컬럼별 비율, 패턴)
② 왜 결측인지 원인 추정 (MCAR / MAR / MNAR)
③ 결측 비율이 과도한 열은 제거 검토
④ 남은 결측은 대치 또는 결측 플래그 추가
⑤ 대치 기준은 train에서만 계산해 나머지에 적용
⑥ 처리 전후 성능을 검증으로 비교
```

### 이전 학습과의 연결

- **"시간의 70~80%는 데이터에 들어간다"** 의 실체가 오늘 내용. → [[2026-07-31-ai-data-ml-lifecycle]]
- **전처리 누수**는 정규화(스케일링)와 대치 모두에서 동일하게 발생한다. `fit`은 train에만. → [[2026-07-31-ai-data-ml-lifecycle]]
- **XGBoost/CatBoost가 결측을 네이티브로 처리**하는 것도, 정규화가 내장된 것과 같은 맥락 — 이 모델들은 생각보다 많은 것을 내장하고 있다. → [[2026-08-05-ai-data-bias-variance]]

| 축약어 | 풀네임 |
|---|---|
| MCAR | Missing Completely At Random |
| MAR | Missing At Random |
| MNAR | Missing Not At Random |
| IQR | InterQuartile Range (사분위 범위) |
